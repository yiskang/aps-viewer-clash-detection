Review complete. The revision improves lifecycle handling, cross-model rejection, and result consistency, but I would not approve it for implementation yet.

1. **[P1] `volume-overlap` still produces false negatives.**
   The vertex-containment predicate at [spec:194](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:194) misses intersecting solids when neither has a vertex inside the other. Two perpendicular elongated boxes can share positive volume while every vertex remains outside the opposite box. The 64-sample cap adds further misses, especially for disconnected components. Proper surface-crossing classification is still required, followed by bidirectional containment for non-crossing cases.

2. **[P1] Ray-parity containment remains underspecified.**
   `MeshBVH.raycast` defaults to front-face-only testing, which is unsuitable for parity unless `DoubleSide` is explicitly requested. The design also needs rules for deduplicating coincident triangle hits, detecting inconclusive edge/vertex crossings, choosing retry directions, and defining `coplanarEpsilon` and its units. Otherwise even a contained box can be classified incorrectly. See the upstream [`MeshBVH.raycast` contract](https://github.com/gkjohnson/three-mesh-bvh/blob/master/API.md#raycast).

3. **[P1] Geometry normalization only partially fixes the previous range issue.**
   The fallback at [spec:146](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:146) omits standard `geometry.index.array` and interleaved `position.data.array` layouts. It clips `drawRange` only when groups are absent, although rendering uses the intersection of `drawRange` and each group. Legacy `offsets` are still silently treated as a full range with `baseVertex: 0`. Standard three.js exposes the index separately from attributes ([BufferGeometry documentation](https://threejs.org/docs/pages/BufferGeometry.html)), and its renderer intersects group and draw ranges ([renderer source](https://github.com/mrdoob/three.js/blob/dev/src/renderers/WebGLRenderer.js#L1152-L1161)). Unsupported layouts should be explicitly rejected, not normalized incorrectly. Sampling must also use vertices referenced by active ranges, rather than the raw vertex buffer.

4. **[P1] `surface-intersection` is public but has no design.**
   It remains included at [spec:65](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:65) and exposed at [spec:275](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:275), but the module layout, narrow-phase routing, semantics, tolerances, and tests only cover `VolumeOverlapQuery`. Either remove this mode from Milestone 1 or specify and test it.

5. **[P2] Skipped-fragment diagnostics lose query completeness information.**
   A bare `FragmentRef[]` at [spec:296](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:296) cannot identify the reason, source/target role, or candidate pair for which containment was inconclusive. A fragment can succeed against one room and fail against another. Use pair-scoped diagnostics with reason codes, or an explicit strict failure policy.

6. **[P2] BLAS scheduling is only partially resolved.**
   Yielding between builds at [spec:253](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:253) prevents a sequence of builds from becoming one uninterrupted task, but one large synchronous `MeshBVH` construction can still freeze the Viewer. The blocking budget remains deferred at [spec:399](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:399). Milestone acceptance needs a per-build threshold and defined fallback.
