I would not approve the revised specification yet. The five prior findings were addressed, and the `0.9.14` rejection is supported by sufficiently specific registry evidence. Four new blockers remain.

1. **[P1] Open components can produce clean false-positive volume overlaps.**  
   The spec runs containment sampling even for open/non-manifold components and only emits `non-manifold-component` for a **negative** result ([spec:612](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:612), [spec:823](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:823)). An open triangle entirely inside a closed box has zero volume, yet one of its vertices classifies inside the box, so `anyComponentInside` returns true and `volume-overlap` reports a clean clash. Containment can establish positive volume only for components certified as closed solids; open/non-manifold components need a different rule or an explicitly unverified result shape.

2. **[P1] Target-wide ray parity implements XOR, not the specified union of components.**  
   `classifyPoint` counts hits across the target’s entire BVH ([spec:576](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:576)). For two nested closed components treated as additive solids, a point inside both crosses two shells and is classified outside. Consequently, a small source inside two concentric target boxes produces a clean false negative despite every component being manifold. Either classify each target component separately and combine with union semantics, or define and test an even-odd shell-fill model; the current “any component” composition and exactness claim do not match global parity.

3. **[P1] The constructed witness reintroduces the tolerance-frame mismatch.**  
   `offsetLadder` is defined in the canonical operand’s frame using `L_canonical` ([spec:427](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:427)), but the witness applies those offsets to triangles in the source component’s local frame ([spec:634](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:634)). If the source sorts second and the local scales differ, a rung can step completely through the source or remain within its boundary epsilon. Direct BVH queries operate in BVH-local coordinates, so this stage needs a separate source-local witness ladder scaled by `L_source`. [Upstream local-frame contract](https://github.com/gkjohnson/three-mesh-bvh/blob/v0.9.14/README.md#gotchas).

4. **[P1] Raw `bvhcast` work remains unbounded and synchronous.**  
   The only crossing budget counts confirmed non-coplanar intersections, explicitly excluding raw candidate pairs ([spec:544](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:544)). Two sub-20,000-triangle meshes can have heavily overlapping BVH leaves but no triangle intersections, forcing an enormous synchronous candidate loop without ever consuming that budget. This contradicts the later claim that the budgets bound the worst case ([spec:1034](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:1034)) and can still freeze the Viewer. Add a raw-candidate budget with an inconclusive diagnostic, or provide a chunkable/off-thread traversal.
