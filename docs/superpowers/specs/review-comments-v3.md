Review complete. I would not approve the revised specification yet.

1. **[P1] `volume-overlap` still treats zero-volume contact as overlap.**
   The design explicitly returns `true` for every `SurfaceIntersectionQuery` hit, including face, edge, and vertex touching ([spec:279](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:279)). Documenting this behavior does not resolve the earlier correctness finding: the idea defines volume overlap as two solids sharing volume and defines touching separately ([idea:1061](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/ideas/aps-viewer-clash-detection-library-idea.md:1061)). It can still report the wrong adjacent room when an element merely touches a shared boundary. Either classify proper crossings, rename the mode to contact-or-overlap, or narrow the Milestone 1 API semantics.

2. **[P1] Capped sampling still has acknowledged false negatives.**
   The 64-point cap does not guarantee coverage of disconnected components, and the spec explicitly defers connectivity analysis ([spec:289](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:289)). For example, if one unsampled component is contained in B while all sampled components are outside, there is no surface intersection, B’s vertices need not be inside A, and the query returns a false negative without a diagnostic. Additionally, “up to 64” conflicts with a minimum of eight samples per range when there are more than eight active ranges. Require coverage per connected component, scan all referenced vertices, or define an explicitly approximate query mode.

3. **[P1] The parity epsilon mixes incompatible coordinate spaces and units.**
   Lines 303–311 use one world-distance `coplanarEpsilon` both for ray-hit distances and barycentric coordinates. Barycentric coordinates are dimensionless, while `MeshBVH.raycast` arguments, hit points, and distances are in BVH-local space, not Viewer world space ([upstream source](https://github.com/gkjohnson/three-mesh-bvh/blob/master/src/core/MeshBVH.js)). The alternate “world axis” direction must also be transformed into the target BVH’s local frame. Specify separate dimensionless and distance tolerances, world/local conversion under scaled transforms, and hit sorting before distance deduplication.

4. **[P2] Room discovery is cached per model but is not model-scoped.**
   The spec calls `viewer.search(...)` while keying the result by `model.id` ([spec:339](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:339)). The installed typings expose the five-argument, `searchHidden` form on `Model.search` ([types:835](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/node_modules/@types/forge-viewer/index.d.ts:835)); `Viewer3D.search` is declared with only four arguments ([types:1247](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/node_modules/@types/forge-viewer/index.d.ts:1247)). Use `model.search(...)` so the cached IDs actually belong to the cache key and the option is honored.

5. **[P2] Diagnostics still lose role and completeness information.**
   `ClashDiagnostic` requires `sourceFragment` and omits `targetFragment` for geometry-normalization failures ([spec:409](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:409)). It therefore cannot accurately represent an unsupported target-room fragment. Also, `inconclusive-containment` is emitted only when *every* sample is inconclusive; a negative result containing some conclusive-outside samples and some inconclusive samples may still be incomplete. Use role-aware fragment diagnostics and emit a pair diagnostic whenever unresolved samples/components could affect a negative result.

6. **[P2] `firstHitOnly` remains an undesigned public option.**
   It is exposed at [spec:383](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:383), but the data flow and tests never define whether it stops after a fragment hit, the first aggregated dbId pair, or the first pair per source, nor how partial diagnostics/statistics are reported.
