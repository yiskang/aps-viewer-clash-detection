I would not approve the specification yet. The round‑6 changes are present, but four P1 issues remain.

1. **[P1] The B5 “degenerate source” correction is not implementable as specified.**  
   The spec says only closed components establish positive volume ([spec:604](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:604)), then allows open source components to produce positive `volume-overlap` results while diagnosing only “genuinely degenerate” ones ([spec:837](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:837)). No algorithm, metric, or threshold distinguishes a nearly closed bathtub from a zero-volume sheet. The API and error sections still say any open positive is diagnosed ([spec:1065](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:1065), [spec:1120](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:1120)), while another paragraph says positive witnesses need no diagnostic ([spec:1088](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:1088)). The spike implementation still flags every non-closed source and tests only the triangle case ([geometry-core:247](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/spike/geometry-core.mjs:247), [fixtures:120](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/spike/fixtures.mjs:120)), so “20/20” does not validate the revised rule.

   This needs one explicit semantic choice: suppress open-source containment from `volume-overlap`, define a concrete volumetric reconstruction/degeneracy rule, or introduce a room-containment mode whose contract permits surface samples.

2. **[P1] Open targets can still produce clean unsound results.**  
   The new text correctly says target openness makes parity unreliable ([spec:848](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:848)), but the algorithm and diagnostic rules only describe flagging the sampled source component. A closed source classified against an open target can therefore return a clean positive even though the parity result is meaningless. Require the entire parity target to be certified closed, or propagate an unverified-target diagnostic to every result depending on it.

3. **[P1] `surface-intersection` still has unbounded synchronous candidate work.**  
   The new raw-candidate budget applies only to `ProperCrossingQuery`’s `bvhcast` callback. The public `surface-intersection` mode still directly invokes `MeshBVH.intersectsGeometry`, with no abort or candidate counter. Upstream traversal performs nested triangle tests until a hit or full exhaustion ([upstream implementation:77](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/node_modules/three-mesh-bvh/src/core/cast/intersectsGeometry.generated.js:77)). Heavily overlapping BVHs with no triangle contact can therefore freeze the Viewer despite the claim that budgets bound worst-case work.

4. **[P1] Empty standard `BufferGeometry.groups` can normalize to zero triangles.**  
   The adapter distinguishes “groups present” from “groups absent” ([spec:450](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:450)), but standard `BufferGeometry` initializes `groups` to an empty array ([three source:164](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/node_modules/three/src/core/BufferGeometry.js:164)). A literal implementation takes the groups branch and emits no ranges. Specify `groups.length > 0`; otherwise synthesize the full range. The fixture must cover `groups: []`, not merely an absent property.

Two smaller inconsistencies should also be cleaned up:

- The classifier defines three generic directions but later says to retry once along an “alternate local axis,” potentially reintroducing spike defect A1 ([spec:784](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:784), [spec:800](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:800)).
- Welding is load-bearing, but its position epsilon remains undefined and explicitly “unexamined” ([spec:618](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:618), [spec:1322](/Users/kangea/Documents/Workspace/Codes/aps-viewer-clash-detection/docs/superpowers/specs/2026-08-06-collision-library-milestone1-design.md:1322)).

Retaining the BVH despite spike finding B7 is defensible because this milestone explicitly begins the general-purpose collision library; I would not treat that rejection as a blocker.
