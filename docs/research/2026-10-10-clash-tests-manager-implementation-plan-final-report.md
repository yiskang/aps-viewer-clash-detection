## Third remediation (2026-10-10, documents only)
Fault-state re-review M1: a faulted result row (`li role=option`) was only given `aria-disabled` + `aria-describedby`; it kept `tabindex="0"` and its `results.js` click and Enter/Space handlers, had no disabled look, and the DOM test never activated it. *Correction of the second-remediation claim:* that pass closed the Medium for native controls only; result-row selection was not genuinely disabled. Corrected in plan Task 11, manager-only (no editor renderer/controller/ViewModel or `FAULT_POLICY` change; AC-M13 intact):
- **`lockRow`** (called by `lockEditor` for a node without native `disabled`): `data-fault-locked="true"`, `aria-disabled="true"`, `aria-describedby` → fault banner, `tabindex` removed (out of the tab order, not focusable), blurred if `rebuild()` had just restored focus to it. Reversal is by construction: `results.js` rebuilds every row on each render, so an un-faulted render yields unlocked rows (pinned by the test).
- **`guardLockedRows`** (installed once per editor host by `renderManagedPanel`): capture-phase `click`/`keydown`/`keyup` listener that calls `preventDefault` + `stopImmediatePropagation` for any event targeted inside a locked row. It precedes the row handler because DOM dispatch runs ancestor capture listeners before target and bubble listeners, the row's handlers are ordinary non-capture listeners on the `li` (`results.js:19–29`, `dom.js` `el()`), and the editor host is a strict ancestor of every row.
- **Disabled look:** `.clash-manager-editor .clash-row[data-fault-locked="true"]{opacity:.4;cursor:default}` (as `main.css` disabled controls), no hover background (`:not(.clash-row-selected):hover{background:transparent}`), no focus ring.
- **Test** (new, Task 11): the same synthetic (row click, child click, Enter, Space keydown) and real (forced click, focus + Enter/Space) inputs dispatch 7 `NAV_SELECT` unfaulted, 0 faulted, 7 again after an un-faulted render; a real Tab sweep reaches both rows unfaulted and none faulted; computed cursor/opacity/hover background change; `aria-disabled`/`aria-describedby` → banner present; double faulted render (idempotent). DOM counts: Task 11 106 + 9, Task 13 106 + 13.
- **L1:** Task 9 Step 2 now expects the module-link failure first — `SyntaxError: The requested module '../../../clashpanel/core/testsManager.js' does not provide an export named 'FAULT_POLICY'` (message form checked with a scratch import on Node v22.23.1; no plan test was run) — and the recovery assertion failures only after the export exists.
