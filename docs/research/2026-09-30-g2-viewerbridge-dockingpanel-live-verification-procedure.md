### 4.1 Activation, authorization binding, and attempt journal (H1 of the v2 re-review)

**Interlock (all required):** CLI flag `--execute-live-g2`; env `G2_LIVE_AUTHORIZED=YES` (exact string); and **one explicit input `--authorization-record <repo-relative path>`**. Pure function `parseLiveActivation({argv,env})` returns `{authorized, reason, recordPath}`; `main()` throws fail-closed **before** any dynamic `import('playwright')`; no top-level playwright import; `chromium.launch` unreachable before the interlock and the record validation and the durable `AUTH_BOUND` write (source-order tests). The flag/env are not proof of owner authorization; the record below is.

**Authorization record — accepted artifact and deterministic selection.**

- *Type/path:* exactly one regular (non-symlink) UTF-8 markdown file located under `docs/prompts/` inside the repository, whose repo-relative normalized path (no `..`, no absolute path, no symlink component) is given by `--authorization-record`. The harness never searches for or infers "the latest matching prompt".
- *Required owner-authorization wording:* the file must contain each of the following as a whole line, each exactly once (any missing/duplicated/malformed line ⇒ reject):
  - `G2-LIVE-EXECUTION: AUTHORIZED EXACTLY ONE ATTEMPT`
  - `Authorization-ID: <lowercase [a-z0-9-]{8,64}>`
  - `Baseline-HEAD: <40-hex>` (must equal `git rev-parse HEAD` at run time)
  - `Procedure-SHA256: <64-hex>` (must equal SHA-256 of this procedure file's bytes at run time)
  - `Harness-SHA256: <64-hex>` (must equal SHA-256 of the harness file's bytes)
  - `Model-A-URN-SHA256: <64-hex>` and `Model-B-URN-SHA256: <64-hex>` (must equal SHA-256 of the literal URN constants in the harness)
  - `Runtime: viewer=7.124.2 env=AutodeskProduction2 api=streamingV2`
  - optional, zero or more: `Supersedes: <Authorization-ID>`
- *Ambiguity rejection:* the harness enumerates every regular `*.md` file under `docs/prompts/` that contains a line beginning `G2-LIVE-EXECUTION:` (the "candidate set"). It rejects if: the passed path is not in the candidate set; any candidate has malformed marker lines; two candidates carry the same `Authorization-ID`; or the number of **non-superseded** candidates ≠ 1 or that one is not the passed record.
- *Stale/superseded rejection:* a candidate is superseded iff another candidate's `Supersedes:` line names its `Authorization-ID`. The passed record must not be superseded.

**Reservation and journal — durable, per-authorization, monotonic.** Directory `test/acceptance/results/clashpanel-viewerbridge-g2-attempts/`. Two files per authorization: the **reservation** `<Authorization-ID>.reservation.json`, created **exclusively** (`open(path,'wx')`, which fails with `EEXIST` if any other process or earlier run created it) and never modified or deleted afterwards; and the **journal** `<Authorization-ID>.journal.json`, replaced by temp+rename **only by the process that owns the reservation**. The reservation carries the complete binding record (all binding fields below and the fresh `attemptId`); the journal repeats it and appends transitions. Content: `{journalVersion, attemptId (random UUIDv4), authorization:{path, sha256, id}, headSha, procedure:{path, sha256, version:'v5'}, harness:{path, sha256}, fixtures:{A:{name,urnSha256}, B:{name,urnSha256}}, runtimeEnvelopeRequested:{viewer:'7.124.2', env, api}, transitions:[{state, at (ISO-8601 UTC), monotonicMs, detail?}]}`. The `AUTH_BOUND` write carries every binding field; later transitions only append.

| State | Meaning | Entered when | Exits to |
|---|---|---|---|

**Durable write order (H1).** W0 parse interlock (pure). **W1 record validation** — read the record; enumerate and validate the candidate set and supersession; compute SHA-256 of the record, this procedure file, the harness file and the two URN constants; compare `git rev-parse HEAD` with `Baseline-HEAD`; scan the attempts directory (`readdir`, if it exists) for every `*.reservation.json`, `*.journal.json` and `*.journal.json.tmp-*` (startup rule below). W1 consists solely of local reads and pure computation: it touches no Viewer, model, token, browser, network or evidence file, and reserves nothing. **W2a establish the directory chain durably (reserves nothing), then W2b create the reservation exclusively (H1 of the v3 re-review).** *W2a:* `D0 = test/acceptance/` (tracked; must already exist), `D1 = D0/results/`, `D2 = D1/clashpanel-viewerbridge-g2-attempts/`. Every `Di` must be a real directory (`lstat`; a symlink or non-directory ⇒ refuse, exit 1). For `D1` and then `D2`, in this order: (1) if `Di` is absent, `mkdir(Di)` (an `EEXIST` race is accepted only if the result is a real directory); (2) open `Di`, `fsync(DiFd)`, close — makes the new directory's own entries durable; (3) open the parent `D(i−1)`, `fsync(parentFd)`, close — makes the parent's entry for `Di` durable. Step (3) runs **unconditionally, whether or not this process created `Di`** (an existing directory may have been created by an earlier process that died before its parent fsync; the fsync is idempotent). *W2b (only after W2a fully succeeded):* open `D2` and hold `D2Fd`; `open(reservation,'wx')` — on `EEXIST` refuse (another process or an earlier run owns this `Authorization-ID`); write the binding record; `fsync(fd)`; close; `fsync(D2Fd)`; then create the journal by temp+rename with the `AUTH_BOUND` transition (journal durability algorithm below, ending in `fsync(D2Fd)`). Any error from `mkdir`, `open`, `write`, `fsync`, `close` or `rename` in W2a/W2b is a durability failure: stop immediately, no retry, exit 1, no browser/Viewer/token access. Nothing fallible other than W2's own filesystem operations lies between W1 and W2; concurrent harness processes are serialized by the `wx` create — exactly one can win. **Durable-before-effect invariant:** no Phase 0 step, no CDN/token/Viewer/browser access and no W3 write occurs until W2a, the reservation's fsyncs and the `AUTH_BOUND` journal write (with its fsyncs) have **all** completed successfully. Consequently a reservation lost to an OS crash before its fsyncs completed implies that no external effect and no consumption happened, and the record is safely reusable; any reservation that any external effect could have followed is durable together with the directory entries that lead to it (the parent `fsync` of a freshly created attempts directory completed before the reservation was even created). **Only after W2 succeeds** may the harness perform the remaining Phase 0 steps (evidence-writer setup, harness/manifest hashing, git branch/porcelain clean-tree check, served-module manifest, Playwright import, browser/context/page/route/goto, bootstrap-ready, module install). Any failure in those steps ⇒ best-effort `PREFLIGHT_FAILED`. Then **W3 durably write `ATTEMPT_CONSUMED`**; only then the first `loadDocumentNode`. Boundary names are those of the canonical boundary sequence above (B1–B8). Pre-consumption use of the Viewer CDN script, token endpoint and `Initializer` is **not** consumption (G1 precedent) but does spend the record once B3 exists.

**Crash matrix and second-run rejection.** "Durable after" is the worst case after a crash; a *process* crash leaves everything the kernel accepted visible, an *OS* crash may lose anything not yet covered by a completed `fsync`.

| Crash / failure occurs | Durable state after | Same record reusable? | Reader class |
|---|---|---|---|
| during W0/W1 (no file operation on the attempts tree) | none | **Yes** — W1 is side-effect-free | none |
| during W2a: before/after `mkdir(D1)`/`mkdir(D2)`, after the new directory's own `fsync`, before/after the parent `fsync` (any subset may be lost by an OS crash; a process crash leaves any created directories, empty) | directory chain possibly absent, possibly present and empty; **no reservation** | **Yes** — no reservation was created yet (W2b starts only after every W2a fsync completed); no external effect occurred | none |

| same point, **OS crash** | reservation and/or directory may have vanished — or survive | **Yes only if nothing survived**; safe because of the durable-before-effect invariant (nothing external and nothing consumed had happened). Because the entire directory chain, the reservation and its directory entry are durable **before** the first external effect, no crash can erase the only durable indication that an authorization was reserved or consumed while a later run silently reuses it: the only lossy window is the one in which nothing had yet happened.

*Startup rule (W1):* if `<Authorization-ID>.reservation.json` exists (in any content state), or `<Authorization-ID>.journal.json` exists in any state, or an orphan `<Authorization-ID>.journal.json.tmp-*` exists, or any reservation/journal in the directory has `authorization.sha256` equal to the passed record's SHA-256, the harness refuses (exit 1, fail-closed, reason `reservation-exists`, `journal-exists:<state>`, `orphan-temp` or `unreadable-reservation`). Reservation and journal files whose content cannot be parsed are compared conservatively: an unparseable `*.reservation.json` or `*.journal.json` in the directory ⇒ refuse (`unreadable-reservation`), never skipped. The W2 `wx` create repeats the same check atomically, so two processes that both passed W1 cannot both reserve. A refusal writes nothing. Only a new owner-issued record with a new `Authorization-ID` can license another run.

*Durability algorithm.* Directory chain: as W2a. Reservation: hold `D2Fd`; `open(reservation,'wx')` → write → `fsync(fd)` → close → `fsync(D2Fd)`. Each journal write (only by the reservation owner): `open(tmp,'wx')` in `D2` → write full JSON → `fsync(fd)` → close → `rename(tmp, final)` → `fsync(D2Fd)`; then reopen `final`, read bytes, compare SHA-256 to the intended bytes (write-success verification). Every other durable file in `D2` or `D1` (§9.1 R1–R3, K, F) uses the same write-`fsync(fd)`-close-`fsync(dirFd)`-verify sequence (F via `wx`; K via a `wx` candidate plus one non-overwriting `linkSync` commit, §9.1 step 8; R1–R3 via temp+rename in `D1`, whose own entry in `D0` was already made durable by W2a). **Realistic claim:** the state survives process crash and a normal (buffered) OS crash on a local POSIX filesystem (**except K**, which is atomically visible at B8 but durable only after the step-9 directory fsync; a loss reads `FAIL(commit-missing)`, §9.1 scenario 10); Node cannot request macOS `F_FULLFSYNC`, so **no power-loss durability claim** is made, nor any claim for network or FUSE filesystems; no claim is made about a filesystem that acknowledges `fsync` without persisting. The harness never deletes a journal or rewrites it to an earlier state. **Filesystem assumption (claim scope unchanged):** on the local POSIX filesystem `rename(2)` and `link(2)` are atomic, and a call that returns an error has not taken effect; nothing is claimed for network or FUSE filesystems.

*Failure handling per state:* a durability failure at W2a/W2b ⇒ exit 1 with no `loadDocumentNode` and no browser (a reservation that may exist is treated as spent); a journal write failure at W3 ⇒ no `loadDocumentNode` is issued (fail-closed; the run is a preflight-class failure, journal stays `AUTH_BOUND`); a closeout write failure ⇒ §9.1 (final verdict `FAIL`). **No retry is ever enabled by any failure.**

*Proof of exactly one attempt (what a later reviewer checks):* (1) the journal for the `Authorization-ID` shows exactly one `ATTEMPT_CONSUMED` transition and exactly one `attemptId`; (2) the result JSON's `attempt.attemptId` and every log line's attempt prefix equal it; (3) the spy/load ledger shows **zero to two** `loadDocumentNode` starts, ordered A then B, at most one per fixture, **none before** the `ATTEMPT_CONSUMED` timestamp, and exactly two only for a run that progressed through both load initiations (a consumed attempt that crashed or failed earlier legitimately shows fewer); (4) the journal's `authorization.sha256`, `headSha`, `procedure.sha256`, `harness.sha256`, fixture digests equal the values recomputable from the repository at the recorded HEAD (git history of the committed record); (5) exactly one reservation and one journal exist for the `Authorization-ID`, the reservation's binding record equals the journal's, and no other reservation/journal in the directory has the same record SHA-256; (6) the committed evidence set includes a byte copy of the journal, of R1, R2, R3, of the terminal commit record K (and of F if it exists); K's `resultSha256`/`summarySha256`/`manifestSha256` equal the SHA-256 of the committed R1, R2 and R3, K's `journalSha256` equals the SHA-256 of the committed journal, and the §8 reader function applied to the committed copies returns the verdict the report states.

**Phase 0 preflight (does NOT consume the attempt):** `W0 → W1 → W2 (AUTH_BOUND)` → start time + atomic evidence writer → harness sha256 → git branch/HEAD/porcelain (clean tree required; only `docs/prompts/` untracked allowed — the journal and result directories are git-ignored; the raw log, if any, is written **outside the repo tree** until copied — G1 lesson) → served-module manifest → Playwright import → browser launch/context (`serviceWorkers:'block'`, `deviceScaleFactor:1`)/page/route/goto → bootstrap-ready → module install. Any failure after `AUTH_BOUND` ⇒ overall `FAIL`-with-category, exit 1, journal `PREFLIGHT_FAILED` (best-effort), **attempt not consumed**, recorded separately (G1 precedent); a rerun needs a fresh owner record.

**Attempt consumed** at the completed `ATTEMPT_CONSUMED` durable write. From there: exactly one execution, no retry-until-green, no parameter/assertion/fixture change, no harness/production patch. A defect ⇒ preserve evidence, stop, independent review.

### 4.4 Deterministic target selection

Per model (A, B): enumerate the instance tree leaf dbIds ascending; candidate = leaf with ≥1 fragment and a valid `getNodeBox` (finite, min ≤ max). `a1` = first candidate of A; `b1` = first candidate of B. For the fit-union check (C6) choose the pair (`a*` from A, `b*` from B) among the first 50 candidates of each maximizing the world-space centre distance; ties by lowest dbId. Record all chosen dbIds, the full candidate counts, and the rationale. If no discriminating pair exists (N2) ⇒ C6 `NOT_EVIDENCED`. No selection is randomized.

### 4.5 Timeout contract

Every awaited Viewer/browser operation is wrapped in a token-bounded deadline (G1 token states; late completions quarantined and counted in `staleContinuationsDropped`). A timeout of an operation marks the current check `BLOCKED(timeout:<op>)` (or the control `TIMED_OUT`), sets `sessionTainted=true` when the operation was mutating or its completion is unknown, forbids further **mutating** Viewer calls except cleanup, and proceeds to cleanup. The timeouts that are **FAIL** not BLOCKED are exactly those named in §4.7 (c) E4/E5: absence of a **spec-expected event** within its window (negative evidence), expiry of the whole-attempt cap, and the Phase-0/cleanup step deadlines (via row 5/row 2). All values are frozen in §4.7 (Table T).

Readiness rule for tree enumeration: both models' `OBJECT_TREE_CREATED_EVENT` (or, if a tree already exists, `getObjectTree(cb)` success) **and** the geometry-loaded event as G1's load stages establish; a bounded poll only as G1's accepted fallback, recorded.

### 4.6 Evidence hygiene and call attribution

- **Redaction:** every persisted string (console text, failed-resource URLs, event payload summaries, headers) passes G1's secret redaction (drop query strings, mask bearer/`access_token`/signature patterns); the token response is never persisted. **Size caps:** per-field 4 KiB, spy ledger 2 MiB total, truncation recorded (`truncated:true, originalBytes`). **Verdict-critical fields are exempt from truncation** (verdicts, reasons, journal copy, scene-ownership table, oracle inputs/outputs, `errorLedger.requestFailures[]`/`opLedger[]` (§9.2), the C15(e) observation set and `dependencyBlockedBy` records); if they would exceed a cap the run's evidence write fails visibly rather than truncating them.
- **Wrapper composition and attribution:** all wrappers are created by one `recordingWrap` factory; injection wrappers (C15) are installed **inside** the recorder (recorder outermost). Call origin is assigned by a harness-controlled `withOrigin('harness'|'bridge'|'shell'|'viewer-internal', fn)` context stack, not by phase; a call with no active context is `unattributed`, and an unattributed call to a prohibited method is a C19 FAIL. Offline tests prove injected calls remain recorded and origin stacks nest.

### 4.8 Model ownership and cleanup semantics (M1)

- **What G2 loads:** the harness itself loads model A then model B through G1-style document/node load starters into one `GuiViewer3D`; it assumes nothing pre-loaded. **No registry/catalog/`ModelCatalog`/`wireModelUnload`/registration/re-registration/OQ-1 behaviour exists in G2**; models are raw Viewer `Model` objects, keyed by object identity (never `modelId`).
- **Owner of lifecycle:** the harness owns both models' lifecycle end to end. The ViewerBridge owns only its overlay meshes/scenes it created and its recorded isolation.
- **Allowed mutations of each model:** load; node hide/show (C11: one dbId, restored); model hide/show (C16: B only, restored); aggregate isolation set/restore (C10/C12/C14/C15); `unloadModel(B)` (C17, terminal, **not restored by design**); overlays via the bridge; the harness's own foreign overlay sentinels (§C7/C18). Nothing else.
- **What must be restored:** isolation empty; hidden nodes empty; hidden model shown (C16); harness-hidden node shown; harness sentinel meshes/scenes removed; recording/injection wrappers restored by reference.
- **What survives cleanup:** nothing Viewer-side: cleanup unloads every still-loaded model.
- **Model B after C17:** B has been unloaded by design; its object is stale. After C17 every read is guarded by `getAllModels()` membership; the harness never reloads B.
- **Cleanup — independent guarded unloads (`unloadModelA`, `unloadModelB`):** each step is attempted independently; if the model is absent from `getAllModels()` the step is `already-absent` (success); else `viewer.unloadModel(model)` with T8 deadline; failure recorded; then `verifyViewerModelSetEmpty`. These steps run even if C16/C17 were skipped, tainted or failed.
- **No-Panel-owned-residue proof for both models:** (i) bridge ledger `inspectLedger()===null` and `inspectDisposal()` clean; (ii) spy net `addMesh − removeMesh` = 0 for every Panel-owned scene; (iii) per §C18/§C7 the scene-ownership oracle passes; (iv) for each model still loaded at the check, aggregate isolation has no entry and hidden nodes has no entry; (v) for a departed model (B after C17) Viewer-side isolation/hidden state was destroyed with the model and is **not observable** — the claim for B is limited to (i)–(iii) and the pre-unload/post-`clear()` reads recorded in C17.

At most **one bridge instance exists at any time** (bridge #2 is created and disposed in P5a before bridge #1 exists).

**Dependency table and taint rule.** C1 gates everything — enforced by the **global C1 gate** (§7, RC1-C1): no P2–P11 action (including P2 spy installation and N1) starts before `gates.C1` is recorded, and P2–P11 run only when it is `OPEN`. **C4 Element world-bounds: API validity and componentwise containment (H4).** *Purpose:* verify that the bridge's element-bounds path (used for outlines and fit targets) returns, for sampled elements, a finite world-space box that **fully contains the union of that element's fragment world bounds**; it does not assert equality, nearness or overlap.
- *Candidate bounds source:* the bridge's own path, `viewerApi.getElementWorldBounds(model, dbId)` (→ `getObjectTree()`/`getInstanceTree().getNodeBox(dbId, Float32Array(6))`, returned as `[minx,miny,minz,maxx,maxy,maxz]`), read with no harness transform.
- *Reference bounds source:* the union over **all** fragments of that dbId (instance-tree `enumNodeFragments(dbId, cb, recursive=true)`) of `model.getFragmentList().getWorldBounds(fragId, box)` (public reads; the same fragment-list frame the Viewer renders in). **C15(e) — transient restore failure must not permanently strand Panel-owned isolation (RC1 reconciliation; replaces the former `inspectLedger().isolation` clause).**

*Why the former oracle was impossible (verified against `clashpanel/viewer/ViewerBridge.js` / `isolation.js`).* `releaseHeld()` sets the outer write-ahead ledger `held` to `null` once every marker mesh is removed, **independently of whether `isolation.restore()` succeeded**; `inspectLedger()` returns `null` whenever `held === null`. The isolation session (`isolation.js` `record`) correctly **keeps** its record after a failed restore (`restore()` returns `failed` and does not null `record`), but that record is reachable only through `inspectLedger()` and is therefore **not externally observable** once the markers are gone. C15(e) therefore proves retained retry state **only by its observable consequence** and never requires `inspectLedger()` to expose it.

*Three classes of state (normative).* (1) **Internal retry state** — `isolation.record()`/the outer `held` ledger: *not an oracle input*; the harness records `inspectLedger()` after each `clear()` **as diagnostics only** (`diagnostics.inspectLedgerAfterClear{1,2,3}`), with **no verdict role** (expected `null`; a non-`null` value changes nothing). (2) **Externally observable Viewer state** — the harness's own public read-only calls (`viewer.getAggregateIsolation()`, `viewer.getAggregateHiddenNodes()`, `viewer.getAllModels()`, each canonicalised by the existing isolation canonical form, origin `harness`), plus the passive spy ledger (§4.3: per-call origin, seq, thrown/returned, argument digest) and the ordinary `ClearOutcome` return values. (3) **What the harness may inspect** = class (2) and the `ClearOutcome`s; it may not read bridge internals, call any bridge-private API, or perform any mutating Viewer call from the start of the first `clear()` through the settle of the third. **The single exception:** `inspectLedger()` may be read **during setup only, before the first `clear()`** (where `held` is non-`null`), to establish the setup preconditions (`nm`, `isolation.confirmed`); it can never prove retained retry state, and every post-`clear()` `inspectLedger()` read is diagnostics-only.

*Setup / preconditions (all required; else `BLOCKED(precondition:c15e)` with no injection installed — C10's own verdict, if FAIL, stands separately).* Bridge #1 exists; the phase-boundary baseline invariant holds; `E0 := canonical(getAggregateIsolation())` is the empty isolation and `H0 := canonicalHidden(getAggregateHiddenNodes())` is `[]` (the baseline-empty hidden state; definition below). `r = await present({sides:[{A,a1},{B,b1}], options:{focus:false,isolate:true,marker:true}})` (deadline T5) completes with isolation applied; `T_iso := canonical(getAggregateIsolation())` is **non-empty and ≠ E0**, equals the argument of the bridge-origin `setAggregateIsolation` call that applied it, and `inspectLedger()` (legal here: `held` is non-`null`) shows `markerMeshes.length` = T13 expected count `nm` and `isolation.confirmed === true` (recorded as `nm`, `ledgerBefore`). **`H_iso` capture (RC1-C1).** Immediately after `r` settles and the `T_iso` read — before `W_e` is installed and with no intervening mutating Viewer call by harness or bridge (spy-ledger proven) — the harness reads `H_iso := canonicalHidden(getAggregateHiddenNodes())` exactly once (origin `harness`; a read, legal during setup). `H_iso` may be `[]` or non-empty: whether Viewer 7.124.2 reports the Panel isolation's derived hidden nodes is C10's residual-(a) observation, and G2 presupposes neither. An `unreadable` `H_iso` ⇒ `BLOCKED(precondition:c15e)` with no injection installed.

*Hidden-state observable and equality rule (RC1-C1; resolves H1 of the RC1 independent review; consistent with C10).* `canonicalHidden(raw)` uses the same canonical form as the isolation values `E0`/`T_iso` (C9/C10): `raw` must be an array of per-model entries normalizable by the bridge (C9); each entry maps to `{model:modelKey(entry.model), ids:<ascending, de-duplicated integer dbIds>}`, where **`modelKey`** is the single stable model-key function used by every canonical isolation and hidden value in G2 (`E0`, `H0`, `T_iso`, `H_iso`, every `after` read): `modelKey(m) = 'A'` iff `m` is (by object identity, `===`) the model object returned by the harness's own load of model A, `'B'` iff it is that of model B, and **any other value** (another model object, a model id, a missing model) makes the whole read `unreadable`; entries of the same model are merged (set union), entries with empty `ids` are dropped, entries are sorted by model key; the baseline-empty value is exactly `[]`. A read that throws, is not an array, contains an entry whose model is not A or B by `modelKey`, names a model absent from `getAllModels()` or contains a non-integer id has the exact value `{"unreadable": true, "error": <redacted string>}`, which is equal to nothing. **Equality:** `hiddenEquals(x, y)` ⇔ both are canonical arrays and `JSON.stringify(x) === JSON.stringify(y)` (exact per-model set equality — no subset, superset or tolerance); `isolationEquals` on canonical isolation values uses the same byte-equality rule. **Expected observable sequence:** setup — isolation `E0`, hidden `H0 = []`; after the successful setup `present()` — isolation `T_iso` (≠ `E0`), hidden `H_iso` (any canonical value); after clear #1 (injected throw-before-apply, `o1.isolation = 'failed'`) — isolation `= T_iso` **and** hidden `= H_iso`: the Panel isolation is still applied, so the hidden read must be **unchanged from the post-present capture, not baseline-empty** (verified against the source: `ViewerBridge.releaseHeld()` removes the marker meshes and then calls `isolation.restore()` in `finally`; `restore()` issues no hidden-node write and keeps its record when `restoreTo()` returns `failed`); after clear #2 (`restored`) — isolation `= E0` and hidden `= H0 = []`; after clear #3 (`none`) — isolation `= E0` and hidden `= []`. Post-`clear()` `inspectLedger()` values remain diagnostics-only and enter no comparison.

**Allowed terminal states per control (exhaustive):** N1 ∈ `DETECTED | NOT_DETECTED | NOT_RUN_DEPENDENCY_BLOCKED`; N2 ∈ `DETECTED_RESTORED | NOT_DISCRIMINATING | NOT_DETECTED | RESTORE_FAILED | TIMED_OUT | NOT_RUN_DEPENDENCY_BLOCKED`; N3, N4, N5, N7 ∈ `DETECTED_RESTORED | NOT_DETECTED | RESTORE_FAILED | TIMED_OUT | NOT_EXECUTABLE | NOT_RUN_DEPENDENCY_BLOCKED`; N6 ∈ `DETECTED | NOT_DETECTED | NOT_APPLICABLE` (`NOT_APPLICABLE` only when no `contained` dbId exists, which forces C4 ≠ PASS); N8 ∈ `DETECTED | NOT_DETECTED | NOT_DISCRIMINATING | NOT_APPLICABLE` (`NOT_APPLICABLE` only when C20 did not reach pixel comparison, which forces C20 ≠ PASS). Acceptable states: N1 `DETECTED`; N2 `DETECTED_RESTORED`; N3–N5, N7 `DETECTED_RESTORED`; **`NOT_RUN_DEPENDENCY_BLOCKED` (N1–N5, N7 only) is *neutral for row 4* — it is neither acceptable for PASS (row 8 requires the acceptable state) nor a control failure — if and only if the legality rule below holds; otherwise it is non-acceptable (row 4 `FAIL`)**; N6 `DETECTED`, or `NOT_APPLICABLE` while C4 ≠ PASS; N8 `DETECTED`, or `NOT_APPLICABLE` while C20 ≠ PASS. **`NOT_DISCRIMINATING` (N2 and N8 only) is fixture insufficiency, not a harness defect:** C6 (resp. C20) ⇒ `NOT_EVIDENCED` ⇒ overall `PARTIAL`. Any other state ⇒ control failure ⇒ overall `FAIL`.

**Dependency-blocked control — contract and legality rule (RC1; resolves X4, Option B).** *Decision and basis.* The accepted text states, in three places, that loss of a model prerequisite before any check runs is `BLOCKED`, not `FAIL`: §3 ("model B cannot be loaded, or the classifier is not `CONFIRMED_SVF2` ⇒ dependent checks `BLOCKED`"), §5 ("C1 gates everything"), and §8 row 6 (classifier ≠ `CONFIRMED_SVF2`; model A or B unloadable). The control table, however, defined no state for a control that never started because C1 gated it, so N1/N2 `NOT_DETECTED` and N3/N4/N5/N7 `NOT_EXECUTABLE` made row 4 match first and row 6's own model-loss clauses unreachable (review H2). Option A ("model loss after consumption ⇒ `FAIL`") would leave those two row-6 clauses dead and contradict §3; the procedure already has the same pattern for N6/N8 (`NOT_APPLICABLE` is neutral exactly while its associated check C4/C20 is not `PASS`). RC1 therefore adds the **minimum** analogue — one new terminal state, `NOT_RUN_DEPENDENCY_BLOCKED` (**NRDB**) — and **no other exception**. *Legality rule (RC1; made mechanically decidable by RC1-C1).* A control `N ∈ {N1,N2,N3,N4,N5,N7}` may record NRDB **only if all of the following hold, else NRDB is illegal and is treated as a non-acceptable state (row 4 `FAIL`)**: (L1) `checks.C1` has `verdict:'BLOCKED'` and `reason` **exactly** one of the two normalized C1 reasons `'prerequisite'` | `'timeout:load'` (C1 reason contract below) — the notation `BLOCKED(x)` used throughout this procedure is shorthand for `{verdict:'BLOCKED', reason:'x'}`, and L1 compares **both** fields by exact string equality (a detailed or suffixed string such as `prerequisite:model-not-loaded:B` is **not** a normalized reason and makes L1 false) — **no other C1 cause, and no BLOCKED of any later check (mid-run timeout, taint, `phase-run-threw`, `driver-missing`, `invalid-or-missing-page-record`, `harness-exception`), makes NRDB legal** (a `sessionTainted` set by the P1 load timeout itself does not affect legality); (L2) the control's record is a synthetic **`gate-disposition` record** (RC1-C2, defined below) with `disposition:'NOT_RUN_DEPENDENCY_BLOCKED'` whose `executionRecord` is the exact **not-started** value defined below with `terminalState:'NOT_RUN_DEPENDENCY_BLOCKED'` — NRDB in a `control-run` record is always illegal —, and no spy-ledger, `opLedger`, wrapper, event-log or request/response record is attributed to the control (attribution = the closed-gate evidence predicates CG-1…CG-7 below) — a control that crossed its start boundary keeps its executed terminal state and can never be relabelled NRDB; (L3) the control's `dependencyBlockedBy` is the exact object defined below and satisfies every referential constraint against C1's single retained finalization event; (L4) `gates.C1.outcome === 'CLOSED_DEPENDENCY_BLOCKED'`, the control is listed in `gates.C1.notStarted`, and `gates.C1.c1FinalizedSeq < gates.C1.gateSeq < executionRecord.terminalSeq` (`= dispositionSeq` of its gate-disposition record); NRDB **record legality is exactly L1–L4** and is therefore a pure function of `checks.C1`, `gates.C1`, the control's `recordType`/`disposition`/`executionRecord`/`dependencyBlockedBy` and the attribution fields of the retained ledgers (CG-1…CG-7); it never depends on later events. *Verdict precedence (formerly listed as L5; reclassified by RC1-C2):* rows 1–3 (a fatal event, unresolved cleanup ownership, a check `FAIL`) are not record-legality conditions — they precede rows 4 and 6 and yield `FAIL` regardless of whether an NRDB record is legal. *Non-masking.* A genuine control failure cannot hide behind NRDB: a control that executed and was `NOT_DETECTED`/`RESTORE_FAILED`/`TIMED_OUT` stays unacceptable; a control left unrun for any reason other than (L1) stays `NOT_EXECUTABLE`/`NOT_DETECTED` ⇒ row 4 `FAIL` (so a mid-run timeout or taint that leaves mandatory controls unrun remains `FAIL`, unchanged from the accepted table); C1 itself is a check and a C1 `FAIL` is row 3. *Evidence proving dependency loss rather than a harness defect:* C1's record (`classifier` per model, `runtime[A|B].loaded`, `loadStatus` with the awaited-operation outcome and the T2 deadline record), the absence of any journal/harness exception for P1, `errorLedger.fatalCount === 0` (a network-level request failure during the load is a §9.2 fatal ⇒ row 1 `FAIL`, which is deliberately not converted to `BLOCKED`), each NRDB control's `dependencyBlockedBy` and not-started `executionRecord`, and `gates.C1`. N6 and N8 are unchanged (`NOT_APPLICABLE`, already neutral while C4/C20 ≠ `PASS`).

**C1 reason contract (RC1-C1; normative).** C1's record is the `check-run` record `{recordType:'check-run', verdict, reason, fields, evidence, finalizedSeq:integer, finalizedAt:string}` (C1 never has a `gate-disposition` record, RC1-C2). When C1 is `BLOCKED` because a P1 model prerequisite is unavailable, `reason` is exactly one **normalized** value: `'prerequisite'` (classifier ≠ `CONFIRMED_SVF2` for A or B; a model not loaded or its awaited load rejected; `getAllModels().length !== 2`, T14) or `'timeout:load'` (the T2 load/readiness deadline fired for A or B; it takes precedence when both kinds of cause occur). The detailed cause is retained **only** in `fields.blockDetail = [{cause:'classifier'|'model-not-loaded'|'load-rejected'|'model-count'|'load-deadline', model:'A'|'B'|null, observed:string|null}]` (non-empty; ordered A, B, then model-independent; `observed` redacted), which is diagnostic: **no verdict function, legality test or §8 row predicate reads `blockDetail` or parses `reason`**. Any other non-PASS C1 outcome (a P1 harness exception, a driver error, taint not caused by the P1 load timeout) carries its own reason (e.g. `harness-exception`) and makes L1 false. `finalizedSeq` is the node-side `seq` (§9.2 counter) of C1's single retained finalization event `{seq, kind:'check-finalized', check:'C1', verdict, reason}` in `eventLog`; exactly one such event exists and C1's record is immutable after it.

**`executionRecord` (RC1-C1; exact — every control N1–N8 carries one; all keys required; unknown keys rejected).** `{controlId:'N1'|…|'N8' (= the record's key), phase:'P2'|'P4'|'P5a'|'P6'|'P6b'|'P7'|'P9' (= the control's owning phase in §5), dependencyIds:[string] (exactly the control's row of the *Control dependency ids* table below, always including 'C1', ascending numeric order), started:boolean, crossedStartBoundary:boolean, startSeq:integer|null, startedAt:string|null, terminalSeq:integer, terminalAt:string, terminalState:<the control's §7 allowed-state enum; equals the control record's **effective state** — `state` when `recordType==='control-run'`, `disposition` when `recordType==='gate-disposition'` (a `gate-disposition` record has no `state` field and is not required to)>, result:object|null, evidenceRefs:[string]}` (timestamps ISO-8601 UTC with milliseconds; `seq` values from the single node-side counter of §9.2; `evidenceRefs` are JSON Pointers into R1). The **start boundary** of a control is crossed at its first action of any kind — its first Viewer call, wrapper/spy installation, spy/ledger entry, harness-state mutation, or oracle evaluation over live data; the harness records `startSeq`/`startedAt` **before** that action, and every record attributable to the control has `seq > startSeq`. Exactly two shapes are legal. **Not started** (the exact meaning of the former prose `executionRecord: none`): `started:false, crossedStartBoundary:false, startSeq:null, startedAt:null, result:null, evidenceRefs:[]`, `terminalState ∈ {NOT_RUN_DEPENDENCY_BLOCKED (N1–N5, N7; only inside a `gate-disposition` record), NOT_EXECUTABLE (N3–N5, N7), NOT_DETECTED (N1, N2 — the accepted unrun encoding), NOT_APPLICABLE (N6, N8)}`, `terminalSeq` = the seq at which the state was recorded. A not-started `executionRecord` occurs in a `control-run` record (a control left unrun after an `OPEN` gate) or in a `gate-disposition` record (closed gate); a started one occurs **only** in a `control-run` record. **Started:** `started:true, crossedStartBoundary:true`, integer `startSeq < terminalSeq`, string `startedAt`, `terminalState ≠ NOT_RUN_DEPENDENCY_BLOCKED`, `result` an object (the control's per-control fields), `evidenceRefs` non-empty. Any other combination (e.g. `started:false` with a non-null `startSeq`, `crossedStartBoundary ≠ started`, NRDB with `started:true`) fails `validateResultSchema` (row 5) and, for an NRDB state, also violates L2 (row 4).

**`dependencyBlockedBy` (RC1-C1; exact — key present on every control record and on every `gate-disposition` record (RC1-C2); all keys required; unknown keys rejected).** non-null **iff** the control record's **effective state** (`state` for `control-run`, `disposition` for `gate-disposition`) is NRDB; i.e. `null` for every control whose effective state is not NRDB and for every `gate-disposition` record under a `CLOSED_OTHER` gate. Any comparison or reference to a blocking control/check state in this procedure (the L-rules, X-rows, §4.2 tests, §8, §9.2, §10) uses this same effective-state accessor, never a raw `.state` on a record that may be a `gate-disposition`; for an NRDB control, and for every C2–C20 `gate-disposition` record under a `CLOSED_DEPENDENCY_BLOCKED` gate, exactly `{check:'C1', blockingState:'BLOCKED', reason:'prerequisite'|'timeout:load', phaseSeq:integer, blockedAt:string, evidenceRef:'/checks/C1', failedBeforeDependentStarted:boolean, detail:[…]}`. `reason` is the normalized enum and is the only reason field any verdict input reads — never a free-form or suffixed string; `detail` is a verbatim copy of `checks.C1.fields.blockDetail` (diagnostic, never a verdict input). **Referential constraints (all required for L3):** `blockingState === checks.C1.verdict`; `reason === checks.C1.reason`; `phaseSeq === checks.C1.finalizedSeq`, which is the `seq` of the one retained `check-finalized` event for C1 (not the P1 marker, not the gate seq, not any other event); `blockedAt === checks.C1.finalizedAt`; `failedBeforeDependentStarted === true`, which is legal only when `phaseSeq < gates.C1.gateSeq` and the item's record is a `gate-disposition` record (for a control, with the not-started `executionRecord`); `detail` deep-equals `checks.C1.fields.blockDetail`. NRDB is legal only when this dependency condition holds **and** the control never started; a mid-run failure, taint, timeout or partially executed control can never be relabelled NRDB (L1, L2, L4).

**Record types — run records vs synthetic gate-disposition records (RC1-C2; exact; resolves H1 of the RC1-C1 independent re-review).** Every entry of `checks` (C1–C20) and of `controls` (N1–N8) carries the required discriminator `recordType`, and exactly one of three disjoint shapes is legal (all keys required, unknown keys rejected; a missing or unknown `recordType`, or a shape/`recordType` mismatch, fails `validateResultSchema` ⇒ row 5). **Run records** are written only by the item's own phase-run path (C1 by P1; C2–C20/N1–N8 only after an `OPEN` gate): a **`check-run`** record is `{recordType:'check-run', verdict, reason, fields, evidence}` (C1 additionally `finalizedSeq, finalizedAt`) — the accepted check record plus the discriminator; a **`control-run`** record is `{recordType:'control-run', state, <per-control fields>, executionRecord, dependencyBlockedBy}` — the accepted control record plus the discriminator. A run record may describe an item that did not cross its start boundary (a check left unrun by a mid-run timeout/taint after an `OPEN` gate still gets a `check-run` record `BLOCKED(...)`; a control left unrun after an `OPEN` gate gets a `control-run` record with the not-started `executionRecord` and `NOT_EXECUTABLE`/`NOT_DETECTED`). **Only `check-run` records carry a `verdict`; every runtime `BLOCKED` is a `check-run` record.** **Synthetic `gate-disposition` records** are written only by the gate path, only when `gates.C1.outcome ≠ 'OPEN'`, and then for **every** item of C2–C20 and N1–N8 and for nothing else (C1 always has a `check-run` record). They document why an item did not run; they are not execution records and carry no runtime result. Exact shape: `{recordType:'gate-disposition', itemId:'C2'|…|'C20'|'N1'|…|'N8' (= the record's key), itemKind:'check'|'control' ('check' iff itemId starts with C), synthetic:true, gateGenerated:true, executed:false, gateOutcome:'CLOSED_DEPENDENCY_BLOCKED'|'CLOSED_OTHER', blockingReason:'prerequisite'|'timeout:load'|'closed-other', disposition:string, dispositionSeq:integer, dispositionAt:string, startSeq:null, startedAt:null, executionRecord:object|null, dependencyBlockedBy:object|null, evidenceRefs:['/gates/C1','/checks/C1']}`. **Rules (all mechanically checked; each violation ⇒ row 5, X29):** (G-a) `gateOutcome === gates.C1.outcome`; `blockingReason === checks.C1.reason` (`'prerequisite'` | `'timeout:load'`) iff `gateOutcome:'CLOSED_DEPENDENCY_BLOCKED'`, and `blockingReason === 'closed-other'` iff `gateOutcome:'CLOSED_OTHER'`. (G-b) `disposition` (exact enum): a check ⇒ exactly `'NOT_RUN_C1_GATE_CLOSED'`; a control under `CLOSED_DEPENDENCY_BLOCKED` ⇒ N1–N5, N7 `'NOT_RUN_DEPENDENCY_BLOCKED'`, N6, N8 `'NOT_APPLICABLE'`; a control under `CLOSED_OTHER` ⇒ N1, N2 `'NOT_DETECTED'`, N3–N5, N7 `'NOT_EXECUTABLE'`, N6, N8 `'NOT_APPLICABLE'`. (G-c) `dependencyBlockedBy` is the exact §7 object (satisfying every L3 referential constraint) iff `gateOutcome:'CLOSED_DEPENDENCY_BLOCKED'` and the item is a check or an NRDB control; otherwise `null`. (G-d) `executionRecord` is `null` iff `itemKind:'check'`; for a control it is the exact **not-started** `executionRecord` with `terminalState === disposition` and `terminalSeq === dispositionSeq`; the control's §7 state (read by row 4, 7, 8) is its `disposition`. (G-e) `gates.C1.gateSeq < dispositionSeq <` the `seq` of the `cleanup` marker, and `dispositionSeq` strictly increases in the order C2…C20, N1…N8 (deterministic). (G-f) **No runtime evidence:** `evidenceRefs` is exactly `['/gates/C1','/checks/C1']`, and no record matches a closed-gate evidence predicate CG-1…CG-7 (below). **Semantics.** A `gate-disposition` record (i) satisfies evidence completeness — under a closed gate each of C2–C20 and N1–N8 has exactly one record, its gate-disposition record; (ii) never implies execution (`executed:false`, `startSeq:null`, no evidence); (iii) can never be mistaken for a runtime `BLOCKED` — it has no `verdict` key, every §8 row reads check verdicts **only** from `check-run` records, so a gate-disposition record is neither a `BLOCKED(...)`, a `FAIL`, a `NOT_EVIDENCED` nor a `PASS` check verdict (row 8 is therefore unreachable while one exists; row 6 matches a `CLOSED_DEPENDENCY_BLOCKED` gate through C1's own `check-run` record and its explicit gate clause); (iv) never hides a real failure after a start — it can exist only under a closed gate, the gate is written before any P2 action, and a closed gate coexisting with any downstream run record, any `executionRecord.started:true` or any downstream start/action/evidence record is an evidence contradiction (row 5; a started control keeps its executed `control-run` record and the closed gate itself is then contradicted). Conversely a gate-disposition record under an `OPEN` gate is a contradiction (row 5).

**Global C1 gate (RC1-C1; procedure contract — closes the P2/N1 bypass of RC1 independent review M3).** *Downstream of C1:* every phase P2–P11 and everything in it — checks C2–C20 and controls N1–N8, **including P2's spy installation and N1** (N1 has no check dependency in §5 but is gated all the same). *Gate point:* after the last P1 action and after C1's record is finalized (`finalizedSeq`), and before the P2 phase-boundary marker and any P2 action, the harness appends the exact record `gates.C1 = {gateSeq:integer, gateAt:string, c1Verdict:string, c1Reason:string|null, c1FinalizedSeq:integer, fatalCountAtGate:integer, outcome:'OPEN'|'CLOSED_DEPENDENCY_BLOCKED'|'CLOSED_OTHER', notStarted:[string]}` (all keys required; unknown keys rejected); no record attributable to a P2–P11 check or control may carry `seq < gateSeq`. *Gate preparation (RC1-C2; atomic and synchronous — no `await` and no listener turn in between; in this order):* (1) finalize every still-provisional `responseFailures[]` entry whose finalization point is the gate (`finalizedBy:'gate'`), allocating its `finalizedSeq`; (2) rebuild `correlatedRequests[]`/`fatalWitnesses[]` (§9.2), creating each newly fatal identity's witness and its single `required-resource-failure` entry; (3) recompute the §9.2 `witnessCount` invariant and `fatalCountAtGate`; (4) only then allocate `gateSeq` and append `gates.C1`. Hence every gate-finalized entry has `responseSeq < finalizedSeq < gateSeq`, a witness created by a gate finalization has `finalizedSeq = witnessSeq < gateSeq`, and every witness with `witnessSeq < gateSeq` is counted in `fatalCountAtGate`; an entry with `finalizedBy:'gate'` and `finalizedSeq > gateSeq` is an evidence contradiction ⇒ row 5. *Outcome rule:* `OPEN` iff C1 `PASS` and `fatalCountAtGate === 0`; `CLOSED_DEPENDENCY_BLOCKED` iff C1 is `BLOCKED` with a normalized reason (`prerequisite` | `timeout:load`) and `fatalCountAtGate === 0`; `CLOSED_OTHER` otherwise (C1 `FAIL`; C1 `BLOCKED` with any other reason; any fatal error-ledger event before the gate, which also triggers the existing skip-to-cleanup). *C1 `PASS` (gate `OPEN`):* P2–P11 run per §5 with `notStarted:[]`; every C2–C20/N1–N8 record is a run record (`check-run` / `control-run`) and no `gate-disposition` record exists; any later failure, timeout or taint is handled by the existing rules (`BLOCKED(...)` for checks, `NOT_EXECUTABLE`/`NOT_DETECTED` for unrun controls ⇒ row 4 `FAIL`) and can **never** yield NRDB, because L1 requires C1 `BLOCKED`. *C1 `BLOCKED` with a legal dependency reason (gate `CLOSED_DEPENDENCY_BLOCKED`):* no P2–P11 phase starts, no downstream check or control executes, no downstream action occurs and **no downstream runtime result is fabricated**; after `gateSeq` and before `cleanup` the harness emits, deterministically in the order C2…C20, N1…N8, exactly one synthetic **`gate-disposition` record** per item (rules G-a…G-f above): C2–C20 `disposition:'NOT_RUN_C1_GATE_CLOSED'` with `blockingReason = checks.C1.reason` and a `dependencyBlockedBy` satisfying L3; N1–N5 and N7 NRDB with the not-started `executionRecord` and a `dependencyBlockedBy` satisfying L3; N6 and N8 `NOT_APPLICABLE` with the not-started `executionRecord` and `dependencyBlockedBy:null` (neutral while C4/C20 have no `PASS` `check-run` record); `notStarted` lists exactly C2–C20 and N1–N8; the run proceeds to cleanup and closeout (row 6 `BLOCKED` unless an earlier row matches — X4). *C1 `FAIL` or any other closed cause (gate `CLOSED_OTHER`):* no P2–P11 phase starts and no downstream runtime result is fabricated; the harness emits the same deterministic `gate-disposition` records with `blockingReason:'closed-other'` and `dependencyBlockedBy:null`: C2–C20 `disposition:'NOT_RUN_C1_GATE_CLOSED'`; every control with the not-started `executionRecord` — N1 and N2 `NOT_DETECTED`, N3–N5 and N7 `NOT_EXECUTABLE`, N6 and N8 `NOT_APPLICABLE` — so row 4 (and row 3 for a C1 `FAIL`, row 1 for a fatal event) yields `FAIL`; `notStarted` lists exactly C2–C20 and N1–N8. *Recording of gate-disposition records:* every gate-disposition record has `gateSeq < dispositionSeq` (= its `executionRecord.terminalSeq` for a control) `<` the `cleanup` marker's `seq` (G-e). *Mandatory gate equations (validated offline and at closeout; the stored gate fields are **never trusted**, they are recomputed):* `c1Verdict ∈ {'PASS','FAIL','BLOCKED','NOT_EVIDENCED'}` and `gates.C1.c1Verdict === checks.C1.verdict`; `gates.C1.c1Reason === checks.C1.reason` (`null` iff C1 has no reason); `gates.C1.c1FinalizedSeq === checks.C1.finalizedSeq`, and the `eventLog` contains exactly one `check-finalized` event for C1, whose `seq`, `verdict` and `reason` equal `checks.C1.finalizedSeq`/`verdict`/`reason`; `c1FinalizedSeq < gateSeq`; `fatalCountAtGate` equals the number of fatal error-ledger entries with `seq < gateSeq`, where a network entry is the single entry of a **fatal witness** and its `seq` is the witness's `witnessSeq` (§9.2 — one per fatal correlated request identity, never one per raw event; for a provisional HTTP record never earlier than its `finalizedSeq`), i.e. the `witnessCount` invariant of §9.2 restricted to `seq < gateSeq`; `outcome` equals the value recomputed by the outcome rule above from those fields; `notStarted` equals the recomputed list (`[]` for `OPEN`, exactly C2–C20 and N1–N8 otherwise); **for an `OPEN` gate** every C2–C20/N1–N8 record is a run record and no `gate-disposition` record exists; **for a closed gate** (a) each of C2–C20 and N1–N8 has exactly one record, a `gate-disposition` record satisfying G-a…G-f whose `disposition`, `blockingReason` and `dependencyBlockedBy` equal the recomputed values — these synthetic records are **required** and are not execution records — and (b) **no executed or run-path downstream record exists**, i.e. no record matches CG-1…CG-7 below; a gate can therefore never be recorded closed once any downstream record with `started:true` exists. Any mismatch is an evidence contradiction ⇒ `validateResultSchema` failure and §8 row 5 `FAIL` (X28, X29).

**Closed-gate evidence predicates (RC1-C2; closed enumerated list — the exact meaning of "attributed to a downstream item" in L2, G-f and the gate equations).** *Attribution fields:* every `spyLedger` entry (§4.3), every `stateSnapshots` entry and every `eventLog` entry carries `seq:integer`, `phase:'P0'|…|'P11'|'cleanup'|'closeout'`, `activeCheck:'C1'|…|'C20'|null` and `activeControl:'N1'|…|'N8'|null` (added by RC1-C2 where absent; `activeCheck`/`activeControl` are `null` iff no check, resp. control, is executing at that `seq`); wrapper/spy installation and removal are `eventLog` entries of kind `'wrapper-install'` / `'wrapper-restore'`; raw network events and `requestObservations[]` carry `phase`/`activeCheck` (§9.2); `opLedger` entries carry `phase`/`invokedBy` (§9.2). With `cleanupSeq` = the `seq` of the `cleanup` marker, a record is a **prohibited downstream-execution record** under a closed gate iff it matches one of: (CG-1) `markers[]`: `name ∈ {P2,…,P11}`. (CG-2) `spyLedger[]`, `stateSnapshots[]`: `gateSeq < seq < cleanupSeq`; or `phase ∈ {P2,…,P11}`; or `activeCheck ∈ {C2,…,C20}`; or `activeControl ≠ null`; or `phase ∈ {cleanup, closeout}` with `activeCheck ≠ null`. (CG-3) `eventLog[]`: `phase ∈ {P2,…,P11}`, `activeCheck ∈ {C2,…,C20}` or `activeControl ≠ null`; `kind:'check-finalized'` with `check ≠ 'C1'`; `kind:'wrapper-install'` with `seq > gateSeq`. (CG-4) `opLedger[]`: `phase ∉ {P1, cleanup}`, `invokedBy ∈ {C16, C17}`, or a `load` record with `startSeq > gateSeq`. ## 8. Overall verdict model — fail-first precedence (proposed — D2)

Per-check: `PASS | FAIL | BLOCKED | NOT_EVIDENCED`. `computeOverall(state, phase)` has exactly **two** operational phases, both evaluated **before K exists**: `phase='pre-closeout'` (after cleanup, §9.1 step 1; yields `primaryOverall`) and `phase='pre-link'` (the PASS-eligibility gate of §9.1 step 8(a): the same ordered pass over the *current* state plus **only the closeout predicates knowable before K exists** — `CLOSEOUT_STARTED` durable and verified, R1/R2/R3 written and verified, Kc written and verified, `snapshotEqual`, quiescence complete, no fatal event or overdue deadline since step 1, `closeoutFailures` empty; it returns the verdict the commit would carry, `preLinkOverall`). **There is no `phase='final'` evaluation and no evaluation of any predicate that depends on K.** `finalOverall` is not computed by `computeOverall`; it is *assigned* by the commit: `finalOverall = primaryOverall` synchronously iff `linkSync(Kc, K)` succeeds (the gate having required `preLinkOverall == primaryOverall`), and `finalOverall = FAIL` on any pre-link closeout failure or a `linkSync` error (§9.1 step 10). Each evaluation is a **single ordered pass; the first matching row returns; every row's predicate reads only recorded verdicts/ledgers/pre-link closeout facts (never the result of a later row), and every FAIL-producing row is evaluated over the full recorded set even when other checks are `BLOCKED`**. No later row can overwrite an earlier result, and a `BLOCKED` check record can never mask a FAIL elsewhere. The pre-link gate can only **worsen** a pre-closeout verdict (to `FAIL` via row 5 or, for a late fatal event, row 1), never improve it.

| Row | Overall | Predicate (first match wins) |
|---|---|---|
| 1 | `FAIL` | `fatalErrorObserved` (page error, unhandled rejection, required-resource failure = a `requestfailed` event or an HTTP response with status ≥ 400 classified `fatal-required-resource` or `unknown-fatal` by §9.2 (RC1-C1; counted once per correlated request identity through its single fatal witness, RC1-C2), crash/close outside cleanup, WebGL context loss, non-allow-listed `console.error`, uncaught injected error) |
| 2 | `FAIL` | `cleanupUnresolvedOwnership` (ownership of a Viewer/harness resource remains unresolved after re-check) |
| 3 | `FAIL` | any required check C1–C20 has verdict `FAIL` (check verdicts are read **only** from `check-run` records; a `gate-disposition` record has no verdict, §7); **or `phase-run-failed`: R1's `phaseRunFailure` is non-null (a failed phase run — §9.1 *Failed-run closeout*, §10)** |
| 4 | `FAIL` | any mandatory negative control is in a non-acceptable state (§7 — a control's state is its `control-run` `state` or its `gate-disposition` `disposition`), including N1 `NOT_DETECTED` **and any `NOT_RUN_DEPENDENCY_BLOCKED` that violates the §7 legality rule (L1–L4; NRDB is legal only inside a `gate-disposition` record)**; a *legal* NRDB is neutral here |
| 5 | `FAIL` | authorization/journal/evidence contradiction or failure: (**phase-parameterised journal predicate:** pre-closeout — the transition history does not contain **exactly one** `ATTEMPT_CONSUMED` or the last durable state is not `ATTEMPT_CONSUMED`; **pre-link — the history is not exactly `AUTH_BOUND → ATTEMPT_CONSUMED → CLOSEOUT_STARTED` for one `attemptId`, or the journal bytes differ from those hashed for Kc**) or `attemptId`/record-digest/HEAD/procedure/harness/fixture digests differ from those recorded; script-integrity `MISMATCH`/`FETCH_FAILED`/out-of-enum; `ATTEMPT_DEADLINE`; **(pre-link only) any closeout failure knowable before K exists (§9.1 steps 2–8(a)): journal `CLOSEOUT_STARTED` write/verification failure, R1/R2/R3 write/verification failure, K candidate write/verification failure, `r1-mutated`, or `late-verdict-change`** — regardless of what `primaryOverall` was. (A `linkSync` error is not an evaluation input: it *assigns* `finalOverall = FAIL`, §9.1 step 10.) |
| 6 | `BLOCKED` | **only if rows 1–5 did not match:** a prerequisite/evidence is unavailable — classifier ≠ `CONFIRMED_SVF2` for either model; script integrity `PROVENANCE_AMBIGUOUS`/`CAPTURE_UNAVAILABLE`; model A or B unloadable (the cause of any legal `NOT_RUN_DEPENDENCY_BLOCKED` control, §7); any `check-run` record `BLOCKED(...)` (including `BLOCKED(session-tainted)` / `BLOCKED(timeout)`); `gates.C1.outcome === 'CLOSED_DEPENDENCY_BLOCKED'` (its synthetic `gate-disposition` records are **not** check verdicts and never count as a runtime `BLOCKED`; this clause and C1's own `check-run` record carry the row); or `sessionTainted=true` regardless of whether any later check existed to receive a `BLOCKED` record |

| 8 | `PASS` (at both phases this means `PASS`-eligible; the run verdict PASS exists only once K is committed) | none of rows 1–7 matched, i.e. every check C1–C20 has a `check-run` record with `PASS` (no `gate-disposition` record exists), N1 `DETECTED`, N2–N5,N7 `DETECTED_RESTORED`, N6 `DETECTED`, N8 `DETECTED`, integrity `VERIFIED`, cleanup complete, `sessionTainted=false`, `phaseRunFailure === null` (defence in depth: a failed phase run is never PASS-eligible), journal consistent, and — **in the pre-link phase only** — the **pre-link closeout prerequisites** (R1, R2 and R3 written and verified; journal `CLOSEOUT_STARTED` durable and verified; Kc written and verified; `snapshotEqual`; quiescence complete; `closeoutFailures` empty). **`closeoutComplete`** (= K committed by a successful `linkSync`) is the **postcondition** of a successful PASS commit and is never a predicate of any evaluation that precedes K. |

**Root failure of a failed phase run (`phase-run-failed`, owner-authorized failed-run reconciliation).** A non-null R1 `phaseRunFailure` (§10) is the run's **durable root failure**: a separate record, set only by Node, distinct from every row verdict and from the error ledger. It is **never replaced, edited or removed** by a later cleanup or closeout failure; such failures only **add** further `FAIL` reasons — a cleanup-evidence fatal is an `errorLedger.entries[]` entry with `seq > failureSeq` (⇒ row 1, which still wins over row 3, as does row 2), and a closeout failure adds its causes to F / the journal `FAILED` detail (§9.1 step 10), F additionally carrying the same `phaseRunFailure`. The phase failure itself is **not** converted into a fatal error-ledger event; it selects row 3 deliberately (previously a failed run reached row 4 only incidentally through its not-started controls). Rows are not reordered. The root failure never erases history: it records mechanically where it fell relative to the authoritative C1 gate (`c1Stage`, §10; boundary in §9.1 *Failed-run closeout*), and a post-C1 failure keeps the gate, C1's record and every check/control record already produced as evidence of what ran before the failure; no retained `PASS` check or executed control can mitigate row 3 (only rows 1–2 precede it). A failed run can never be PASS-eligible (row 8 requires `phaseRunFailure === null`), and closeout success never changes that: `finalOverall = primaryOverall = FAIL`.

`sessionTainted=true` is a row-6 predicate in its own right, but any FAIL in rows 1–5 takes precedence. `PARTIAL` is not `PASS`. **Authoritative verdict rule — reader precedence over durable artifacts only (H2b).** A run's verdict is `deriveVerdictFromArtifacts(attemptsDir, resultsDir, authorizationId)`, a pure function of the files that survive; stdout, the exit code and the harness's in-memory state are informational and are **never** consulted. The function evaluates every witness below that is present and returns the **worst** valid outcome (FAIL > BLOCKED > PARTIAL > PASS); a `FAIL` witness can never be outranked by a later or contradictory file.

The result JSON's own `overall` field is `primaryOverall` and is never authoritative. **Terminal-commit invariant (v5):** a reader derives a run verdict only from K, K is created by one atomic non-overwriting `linkSync` strictly after every closeout verification succeeded (R1, R2, R3 and the K candidate all read back and verified), and after that synchronous `linkSync` returns success the harness performs **no** operation whose failure could change the verdict (only informational post-commit steps). Hence harness and reader cannot return PASS vs FAIL from the same durable artifact set: a `linkSync` error means K does not exist (reader `FAIL`); a `linkSync` success means K exists (reader = `K.finalOverall`, and the harness reports the same). Every partial prefix of the chain — a crash or fault at any step before the `linkSync` — derives `FAIL` (W-3/W-4/W-5). Exit codes follow the harness's `finalOverall`, which equals the reader's verdict for the same artifacts (the harness derives it from the commit outcome, not from a later re-read; the post-commit read-back, directory fsync and candidate unlink are informational and never change it): PASS 0, FAIL 1 (incl. any throw or Phase 0 failure **before B8**), BLOCKED 2, PARTIAL 3, unrecognized 4. **After B8 every operation is wrapped so that no exception, rejection or timer expiry can alter `finalOverall` or the exit code: the exit code is derived from `K.finalOverall` only.**

## 9. Error ledger and cleanup

**Error ledger** (G1 §6.6 semantics): `pageerror`, `unhandledrejection`, **a `requestfailed` event or an HTTP response with status ≥ 400 classified FATAL (`fatal-required-resource` | `unknown-fatal`) by §9.2** ("required-resource failure"; HTTP responses added by RC1-C1; counted exactly once per correlated request identity through its single fatal witness — §9.2, RC1-C2), crash/close outside cleanup, WebGL context loss, non-allow-listed `console.error` ⇒ fatal; `console.warn/info/log` never fatal; **empty allow-list by design**. The harness's own injected throws (C15) are tagged `injected`; an uncaught injected error ⇒ fatal.

**Cleanup ledger (ordered; every step runs; failures recorded, not blocking; each step bounded by T8):** `drainPendingTokens` → `bridgeDispose` (whichever bridge instance exists; await; idempotent) → `shellDispose` → `removeInjectedFailureWrappers` → `restoreRecordingWrappers` (originals restored by reference and verified) → `removeHarnessForeignScenes` (removes sentinels `S1`,`S2` and pre-created foreign scenes; **then** asserts each is absent) → `restoreIsolationEmpty` (harness) → `showHiddenNodes` → `restoreHiddenModel` → `verifyViewerStateBaseline` (isolation empty, hidden empty for every still-loaded model; no scene of any class remains; `sceneOwnership` table final rows recorded) → `unloadModelA` (guarded, independent) → `unloadModelB` (guarded, independent; `already-absent` after C17) → `verifyViewerModelSetEmpty` → `closePage` → `closeContext` → `closeBrowser` → `httpServerOwnership` (server not started by the harness; operator stops). Closeout (§9.1) follows the cleanup ledger and consumes its results. `cleanupUnresolvedOwnership` is true only if ownership remains unresolved after re-check ⇒ §8 row 2.

**Marker and failure-detail retention for a failed phase run (owner-authorized failed-run reconciliation; normative).** *Phase run failure* = the in-page P1…P11 runner throws, or the Node RPC that drives it does not complete (threw, timed out, or any other non-completion status); an RPC that reports completion but returns a missing or falsy result is likewise a phase run failure, with status `invalid-result` (reason `phase-run-invalid-result`, message `phase run completed without a result`) — never labelled `completed`. *Caller-owned marker log:* the in-page runner receives a caller-owned marker log (`markerLog`) and appends every phase-boundary marker it emits to it, so the markers P0, P1…Pn emitted before a throw survive the throw; on failure the page returns the **whole** log. *Cleanup marker:* if the runner had already allocated `marker:cleanup`, that marker is **reused** (its attribution re-acknowledged) and a second cleanup marker is **never** allocated (it would move the cleanup boundary); otherwise exactly one `marker:cleanup` is allocated, as on a completed run, and appended to the log. *Exact error/detail retention:* before entering cleanup the page captures the error name and message (bounded and redacted, §4.6), the recorder attribution at the time of the throw (`phase`, `activeCheck`, `activeControl`), the `operationId`/`operationType`/`reason` if the thrown error carries them, and allocates one page `alloc` ordinal labelled `phase-run-failure`, which maps to the Node-authoritative `failureSeq` (`seqSource:'page-alloc'`). If the page cannot allocate that ordinal, or the RPC did not complete, Node allocates `failureSeq` at observation (`seqSource:'node-observed'`, `source:'node-phase-run-transport'`, `realm:'node'`, attribution = Node's own). *Authenticated failure attribution:* for a page failure, `phaseRunFailure.phase`/`activeCheck`/`activeControl` are the attribution Node validated when it ingested the failure's own identity-bound `phase-run-failure` alloc ordinal, never the page's separate claim; a page-reported failure seq that is not such an ingested ordinal is discarded and Node observes the failure (`seqSource:'node-observed'`, attribution null). For both post-C1 stages `failureSeq` must follow `gateSeq`, and an untransferred failure's `gateSeq` is a primary seq allocation (unique, never a page ordinal). *Completed-result retention (ordering; normative):* when a phase driver resolves, the runner validates and merges the driver's returned check/control/extras records into its runner-owned history (the `partialSink` source, with their terminal ordinals allocated) **before** the final attribution-clear fence (`activeCheck`/`activeControl` → null, acknowledged by Node) and before any later phase starts; a fence refusal or throw therefore never rolls back or erases an already-completed same-phase result (e.g. C2/C3 in P3, N1 in P2) — it is recorded as the phase-run failure (`failureSeq` after the last retained terminal ordinal). *Node-authoritative completed-result retention (normative):* after that merge and **before** the attribution-clear fence, the runner awaits a **retain fence** (`__g2NodeSync('retain')`) carrying the page's pending ordinals — ingested exactly like the drain fence (no attribution change, so it does not depend on the clear fence) — and a snapshot taken in the same synchronous tick: the partial history (`partial`, below), every marker so far, `eventLog`, `spyLedger`, `stateSnapshots`, `screenshots` and the page high-water. Node validates the snapshot, rewrites it through the ordinal → seq map at once (a high-water mismatch or an unmapped ordinal is a refusal; no page ordinal and no second sequence survives) and keeps it as **its own** retained snapshot (a Node run-state field, never an R1 key; each accepted snapshot replaces the previous one). A completed post-C1 result is therefore Node-authoritative before any later fence can refuse. A retain refusal fails closed: it is one cross-realm fence violation (a fatal ledger entry, retained as fatal evidence), the page call throws, and that throw is the phase-run failure (the previously accepted snapshot, if any, stays Node's; results Node never accepted are not claimed). Later failures — the attribution-clear fence refusing, the cleanup-entry fence refusing, an RPC that does not complete — only **append** FAIL detail (their violations and the `phaseRunFailure` record, whose `failureSeq` is allocated after every retained seq) and never roll history back: post-C1 failed-run R1 preserves the completed results from the page's failure transfer when cleanup entry succeeds (that transfer wins; the retained snapshot is then not applied, so nothing is duplicated) and otherwise from Node's retained snapshot (§9.1 *Failed-run closeout*). *Retained-evidence completeness:* page evidence admitted from Node's retained snapshot (`eventLog`, `spyLedger`, `stateSnapshots`) is subject, before admission into durable failed-run evidence, to the **same** completeness/provenance validation as transferred page evidence (every ingested `spy`/`event`/`snapshot` ordinal present exactly once at its authoritative seq; no unsourced `spyLedger`/`stateSnapshots` record, no duplicate, mismatched or leaked-ordinal record, and the cleanup-event provenance rules; the validator does not independently source non-cleanup `eventLog` entries — the same pre-existing limit as for transferred evidence), with exactly one scoping difference: the ingested side is restricted to the page ordinals Node had ingested when it accepted that retain fence (later ordinals are legitimately absent; nothing later is claimed); a completeness problem **adds** one fatal (the root `phaseRunFailure` and the validated history are kept, nothing is fabricated, PASS stays impossible). Work that had not completed is never fabricated (it stays blocked/not-started), and PASS remains impossible because `phaseRunFailure != null`. *Page-supplied partial history* is trusted exactly as far as the page's check/control verdicts are for a completed run (no new trust boundary); erasing an executed record is detected only where attributed evidence exists (blocked-item/unstarted-control history rules) — recorded as an open limitation. *Authoritative seq:* every marker's and the failure's `seq` value is Node-authoritative — taken from the single node-side counter (§9.2) through the existing page-ordinal → seq map, unchanged; no page-local ordinal is ever persisted as a `seq`. *Node-retained gate:* when the synchronous Node gate action constructs the authoritative `gates.C1` record (§7 *Global C1 gate*), Node retains that gate in its own run state (a Node run-state field, never an R1 key, never taken from a page claim); it is the sole input of the C1 boundary (`c1Stage`, §9.1 *Failed-run closeout*). *Partial-history transfer:* on a throw the page additionally returns the check/control history the runner had already produced, `partial:{checks, controls, extras, sessionTainted, taintPhase, phaseLog}` (read from the runner's caller-owned `partialSink`) — only records that exist; the in-flight item's record is absent, never fabricated. Node uses `partial` only when its own retained gate exists and ignores it otherwise; top-level `checks`/`controls`/`gates` sent with a failure transfer are always ignored. Only Node sets R1's `phaseRunFailure` (§10); the page reports its raw failure and never sets any verdict field. The resulting R1 contents are those of §9.1 *Failed-run closeout*.

### 9.1 Closeout and evidence-write protocol (H2 of the v2 re-review; acyclic restructure H2a/H2b of the v3 re-review; terminal-commit redesign of the v4 re-review)

A run has a verdict only if **a terminal commit K was created after every required closeout/evidence condition was written and verified.** Evidence durability is a mandatory PASS condition: §8 row 8's **pre-link prerequisites** must hold at the gate, and `closeoutComplete` (K committed) is the resulting postcondition. Boundary names B1–B8 are those of the canonical boundary sequence in §4.1.

**Artifacts and acyclic dependency graph.** Every artifact is produced from facts that already exist when it is written; **no artifact contains its own digest or any fact that first exists at a later step.**

| Id | Artifact | Content (only already-existing facts) | Depends on |

Dependency graph (arrows = "is computed from"): `state → CLOSEOUT_STARTED`; `{state, CLOSEOUT_STARTED, O2} → S*`; `S* → R1`; `S* → R2`; `{R1, R2} → R3`; `{R1, R2, R3, journal} → Kc`; `Kc → K` (byte-identical link). Acyclic; K's own bytes appear in no other artifact; every hash is recomputable by a reader from file bytes.

**R1 payload cutoff (immutable).** *Cutoff event:* the instant step 4 completes — `CLOSEOUT_STARTED` durable, O2 attempted, snapshot **S\*** taken as a canonical plain-JSON object (numbers, strings, booleans, `null`, plain arrays and plain objects only — no typed arrays, `Map`, `Set` or `Date`; the C20 RLE lists and matrices are plain number arrays) whose canonical serialization is hashed as `snapshotSha256`, and `Object.freeze`d recursively as a guard. *Allowed in R1:* exactly the top-level keys of §10 populated from S\* — including `attempt.journalStates[]` ending at `CLOSEOUT_STARTED` and `finishedAt` = the snapshot instant. *Closeout facts that exist only in R3/K/F/later records and are **forbidden** in R1:* any hash of R1/R2/R3/K/the journal after `CLOSEOUT_STARTED`, `closeoutFailures`, `requiredArtifacts`, `verification`, `finalOverall`, any commit or K field, and any journal transition after `CLOSEOUT_STARTED`. *Mechanical enforcement:* `buildResultPayload(S*)` is pure and deterministic; `R1bytes` is serialized **once** and sha256'd once; `validateResultSchema(result,'payload')` enforces a top-level key **whitelist** and a forbidden-key deny-list (unknown or forbidden key ⇒ invalid); before writing R3 and again before creating Kc the harness re-canonicalizes S\* and requires its hash to equal `snapshotSha256` **and** `buildResultPayload(S*)` to re-serialize byte-equal to `R1bytes` (`snapshotEqual`); any difference, or a thrown write to the frozen guard, is closeout failure `r1-mutated`. **O1 is external:** its existence is unknowable to the harness at the cutoff and is never recorded in R1 (only O2's status is). Offline tests inject a late mutation and assert the failure and a forbidden-key rejection.

**Optional artifacts** (**O1** raw log — captured by the operator's stdout/stderr redirect outside the tree, not written by the harness; **O2** PNG copies of the C20 frames): **only O2's** absence or write failure is recorded by the harness in `closeout.optional[]`; **O1 is captured externally by the operator — the harness neither writes, owns nor records O1's status; it is noted later by the reviewer/report and is never part of authoritative verdict reconstruction (§8 W-0…W-6 read only harness-owned files).** Neither has any effect on `overall`, `closeoutComplete` or the commit; no verdict-relevant datum lives only in an optional artifact.

**Order and verification** (each write uses the §4.1 durability algorithm; verification = re-open and read the bytes, compare SHA-256 to the intended bytes, and for R1 `JSON.parse`, `validateResultSchema` and `snapshotEqual`; a verification **read** may be repeated once, identically, before it is declared failed; a failed write is never retried; any write/rename/fsync/`link` error, read fault or mismatch that survives that repeat is a **closeout failure**, and there is no other kind of ambiguity: **an outcome that is not a verified success is a failure**):
1. Compute `primaryOverall = computeOverall(state, 'pre-closeout')` and record the error-ledger fatal count as `fatalCount0`. Required: all checks, controls and cleanup are finished (the browser/context/page are closed by cleanup) and evidence writing has not started; the whole-attempt timer (T9) is disarmed here and closeout has only its per-step deadlines (T8), any expiry of which **before the final critical section (step 8)** is a closeout failure, never a `linkSync` outcome.
2. Durably write journal `CLOSEOUT_STARTED` (B7, the fail-safe non-PASS witness); verify. Failure ⇒ closeout failure; go to step 10.
3. Attempt **O2**; its outcome never affects the verdict.
4. Freeze **S\*** (the payload cutoff).
5. Write **R1**; verify. Write **R2**; verify. Failure of either ⇒ closeout failure (skip to step 10).
6. **Only if R1 and R2 verified:** write **R3**; verify. Failure ⇒ closeout failure (step 10).
7. **Only if steps 2–6 all succeeded — Kc, then quiescence (asynchronous work is allowed here and only here):** create the candidate **Kc** (`open(...,'wx')`, write, `fsync(fd)`, close, `fsync(D2Fd)`); read back and verify the bytes; re-check `snapshotEqual` and that the journal bytes still equal those hashed. Then **quiesce every verdict-bearing asynchronous source**: (i) record, for every deadline the harness armed (T8 per-step, T9, poll deadlines), its absolute monotonic expiry `deadlineAbs` (`performance.now()` basis), then clear the timers and settle every deadline-wrapped operation (a late completion is quarantined and counted, never acted on) — clearing a timer can hide an overdue-but-undispatched expiry, which is why the gate re-checks `deadlineAbs` itself; **every promise the harness creates is tracked in a registry and either awaited to settlement (`Promise.allSettled`) or given its own rejection handler before the barrier — no un-awaited, un-handled promise may exist**, so verdict-bearing rejections are recorded by their own handlers rather than depending on the process-level `unhandledRejection` event; (ii) detach every Playwright page/context/browser listener and every Viewer spy/listener not already removed by cleanup; (iii) drain the event loop: `await` two consecutive `setImmediate` turns plus a microtask flush. **The critical section of step 8 is then entered as the body of a dedicated `setImmediate` macrotask scheduled from the last drain turn's callback — not as an `await` continuation.** Node reports `unhandledRejection` at the end of the tick in which the promise rejected, before the next macrotask starts, so every rejection created during the drain has already reached the ledger handlers when the step-8 macrotask begins (a rejection raised in the same tick as an `await` continuation could otherwise be reported *after* that continuation ran). Any expiry, mismatch, failure or ambiguity up to and including this drain ⇒ **no `linkSync` is attempted**; go to step 10.
8. **Final critical section (B8) — one synchronous, non-yielding block. Selected commit model: synchronous `fs.linkSync(Kc, K)`.** In this exact order and with **no `await`, no `yield`, no `.then`/promise construction, no timer or `setTimeout`/`setImmediate`, no `Promise.race`, no `AbortSignal`, no callback-taking `fs` call and no deadline wrapper** between the first statement and the statement after the `linkSync` returns: (a) *final pre-link eligibility gate:* evaluate `computeOverall(state, 'pre-link')` (§8) over the **current** state and error ledger — rows 1–8 with only the pre-link closeout predicates, **no K-dependent predicate** — and require `preLinkOverall == primaryOverall` with the same row as step 1 (for a PASS commit: `primaryOverall` is PASS-eligible and every row-8 prerequisite, including the closeout prerequisites, holds), `fatalCount == fatalCount0`, and — for every recorded `deadlineAbs` — that `performance.now() ≤ deadlineAbs` for each deadline governing a step not completed strictly before it (an overdue expiry ⇒ `late-verdict-change(deadline-overdue)`); **no `computeOverall(state, 'final')` exists and nothing is evaluated after the `linkSync`** (a fatal event delivered during steps 2–7 — page error, unhandled rejection, T9 expiry recorded, context loss — makes them differ ⇒ closeout failure `late-verdict-change`, **no `linkSync`**); (b) `fs.linkSync(Kc, K)`; (c) the whole block is one `try { gate (a); fs.linkSync(Kc, K); committed = true; finalOverall = primaryOverall } catch { committed = false; → step 10 }`: a throw from (a) or (b) sets `committed = false` and falls to step 10; **synchronously, in the same block**, on `linkSync` return, set `committed = true` and assign `finalOverall = primaryOverall` (by (a) already the pre-link-eligible verdict — PASS when a PASS is committed — so no evaluation is needed; `closeoutComplete` becomes true at this instant as a postcondition); on a thrown error (including `EEXIST`) set `committed = false` and fall to step 10. **Why no race remains:** JavaScript runs this block to completion on one thread, so no timer, promise continuation, event-emitter callback, queued task or fatal event *can* execute between the gate and the syscall result; an event delivered before (a) is seen by the gate, and one delivered after (c) is post-commit. `linkSync` is not wrapped by any deadline: a hung filesystem hangs the process and an external kill is a *crash* (truth-table rows 8–10), never a `FAIL` verdict selected while the link may later succeed. **Result is authoritative:** success ⇒ K exists and the verdict `finalOverall = primaryOverall` is committed; a thrown error ⇒ K does not exist (or is another run's and fails W-5's `attemptId` check) ⇒ reader `FAIL`. **Prohibited implementation patterns** (an offline **AST-level** test (not a token scan) whitelists exactly one direct `fs.linkSync(Kc, K)` call in the critical-section function — no helper, alias, getter or wrapper may reach a link primitive — and rejects each, a real-Node integration test suite (not only fakes) covers a promise rejection raised during the drain turn, an overdue timer, and an event queued around listener detachment (each ⇒ `late-verdict-change`, no link), and a negative control with an asynchronous late-link implementation — `fs.promises.link`, `Promise.race(link, timeout)`, or a fake filesystem whose link settles after a simulated timeout — must be rejected): any of the tokens above between the gate and the statement after `linkSync`; any asynchronous link primitive; any timeout able to select FAIL while a link may still create K. After (c) the harness performs **no** operation capable of changing `finalOverall` or the exit code: every later statement runs inside a catch-all, the process-level `uncaughtException`/`unhandledRejection` handlers ignore events once `committed === true`, and the exit code is derived from the already-assigned `finalOverall`.
9. **Post-commit (informational only, results printed, never affecting the verdict or the exit code):** `unlink(Kc)`; `fsync(D2Fd)`; read K back and compare. A failed directory fsync prints `PASS-UNCONFIRMED` (or the corresponding non-PASS verdict with `-UNCONFIRMED`) and `COMMIT_DURABILITY_UNCONFIRMED`; the exit code still follows `K.finalOverall`, but the operator must run the reader before accepting: an OS crash before the directory entry is durable can lose K and a later reader then returns `FAIL(commit-missing)` — the fail-safe direction; the operator must run the reader on the surviving files before accepting any run.
10. **Closeout failure path** (before a successful B8 commit): best-effort write **F**, best-effort append journal `FAILED`; `finalOverall = FAIL`, exit 1. This path is purely diagnostic — K does not exist, so the reader returns `FAIL` even if F and `FAILED` cannot be written.
11. Print `primaryOverall`, the closeout causes (if any), `finalOverall` and the post-commit observations; exit per §8.

**Terminal-commit scenario matrix** (11 real, distinct scenarios; what the reader `deriveVerdictFromArtifacts` returns; `—` = absent):

**Reader/harness agreement (reconfirmed).** Exact-name K is the only verdict-authoritative artifact. If the harness reports PASS then `linkSync` returned success and a valid K existed at that instant; if K does not exist the reader cannot return PASS; the harness never reports FAIL after a successful `linkSync` (finalOverall is assigned in the same synchronous block and cannot be altered afterward).

**Ambiguity before B8 has no PASS path; B8 is atomic-visible, not power-loss-durable.** The v4 branch "K possibly landed but the harness reports FAIL" no longer exists: K is created only by a successful `linkSync`, and the harness treats *any* pre-commit uncertainty as failure by never calling `linkSync`; a `linkSync` that returns an error has not created K (this rests on the **stated filesystem assumption** of §4.1 — local-POSIX `link(2)`/`rename(2)` atomicity and "an error return means no effect" — which is an assumption to be accepted with D2, not a POSIX guarantee for every fault). The only harness-PASS/reader-not-PASS combination is the OS-crash-before-directory-fsync case of row 10, in which the reader is the fail-safe authority and the process that printed the result no longer exists to contradict it.

**Partial-artifact handling.** Temp and candidate files (`*.tmp-<uuid>`, `*.commit.candidate-<uuid>`) are never authoritative and are unlinked best-effort. A final-named R1/R2/R3 file that fails verification (before a successful B8 commit) is renamed best-effort to `<name>.invalid-<uuid>` and treated as **unwritten**; **K, once linked, is never renamed, unlinked, rewritten or otherwise touched by the harness**, and the `.invalid` rule applies to no file after B8. The reader rule of §8 (W-0…W-6) decides the verdict.

**Failed-run closeout (owner-authorized failed-run reconciliation; normative).** A failed phase run (§9 *Marker and failure-detail retention*) is closed out by the **unchanged** protocol: steps 1–11 run exactly as for any non-PASS primary — journal `CLOSEOUT_STARTED` → O2 → S\* → R1 (verified, schema-valid) → R2 → R3 → Kc → quiescence → drain → final critical section (step 8, unchanged) → K with `finalOverall = primaryOverall = FAIL`. Nothing in steps 1–11, the step-8 critical section or the K timing changes.
- *R1 of a failed run:* R1 carries the non-null top-level `phaseRunFailure` record (§10), set only by Node, and is schema-valid under the failed-run rules of §10. *C1 boundary (mechanical; owner-authorized post-C1 failed-run evidence correction):* Node decides `phaseRunFailure.c1Stage` solely from **its own** retained authoritative gate (§9 *Node-retained gate*), never from a page claim: **no** retained Node gate ⇒ `'pre-c1'` (`gateSeq`/`gateOutcome` `null`); a retained Node gate **and** a usable partial history — the `partial` of a page failure transfer, or, for a non-transferred failure, the `partial` of Node's own retained snapshot (§9 *Node-authoritative completed-result retention*) — ⇒ `'post-c1'`; a retained Node gate but **no** usable history (neither source exists, or it lacks or contradicts C1) ⇒ `'post-c1-untransferred'`. *Usable-history test:* the Node gate's `outcome` is `OPEN` and that history's C1 record is a valid `check-run` record whose `verdict`, `reason` and `finalizedSeq` equal the Node gate's `c1Verdict`, `c1Reason` and `c1FinalizedSeq`. On both post-C1 stages `gateSeq`/`gateOutcome` are the Node gate's `gateSeq`/`outcome`. *Content by stage:* (i) **`pre-c1` and `post-c1-untransferred`:** `gates` is `null` (**no gate and no C1 finalization is fabricated**; for `post-c1-untransferred` the gate fact survives only in `gateSeq`/`gateOutcome`, the execution history is honestly unavailable and nothing is reconstructed); every check C1–C20 is a `check-run` record `BLOCKED` with reason `phase-run-<status>` (= `phaseRunFailure.status`) carrying `evidence.phaseRunFailure` (a summary `{name, message}` equal to the record's `category` and `message`); every control N1–N8 is a not-started `control-run` placeholder (reason `phase-run-<status>`) whose `executionRecord.terminalSeq` is a real, unique Node-allocated `seq` (never `0`); a `pre-c1` R1 additionally carries **no downstream history** — no marker named P2–P11 and no event, spy entry or snapshot attributed to a downstream phase. (ii) **`post-c1` with an `OPEN` gate:** `gates` is `{C1: <Node's retained gate>}` (the gate and C1-finalization rules apply in full); every check/control record the run had **already produced** is kept verbatim (re-validated Node-side), together with the partial history's `extras` — executed `control-run` records keep their start/terminal seqs and states and are never rewritten to placeholders; only an item with **no** record is represented as a `check-run` `BLOCKED(phase-run-<status>)` carrying the same `evidence.phaseRunFailure` (checks) or as a not-started `control-run` placeholder with a real Node-allocated `terminalSeq` (controls), and such an item carries no attributed history except the in-flight `activeCheck`/`activeControl` (for a non-transferred failure these are Node's last acknowledged ones, set to `null` when Node retained that item as completed). (iii) **a closed gate** (`CLOSED_DEPENDENCY_BLOCKED`/`CLOSED_OTHER`) is never `post-c1`: Node cannot allocate `gate-disposition` seqs that precede the cleanup marker (§7 G-e), so such a failure is `post-c1-untransferred` (the gate's `gateSeq`/`gateOutcome` are recorded in `phaseRunFailure`; `gates` is `null`, nothing is fabricated). In every stage `overall` is `FAIL` (row 3, or an earlier row) and `sessionTainted` is `true`. *Retained page evidence:* for a failure transferred from the page — `eventLog`, `spyLedger`, `stateSnapshots` and `screenshots` as transferred plus the cleanup drain, and `errorLedger.markers[]` = **every** marker emitted before the failure (P0, P1…Pn) + the single cleanup marker + `closeout`; for a non-transferred failure (the RPC threw or timed out) the markers are reconstructed from Node's provenance of the ingested page `alloc` ordinals labelled `marker:<name>`, and no page evidence beyond what Node ingested is claimed; a non-transferred `post-c1` failure carries the `eventLog`, `spyLedger`, `stateSnapshots` and `screenshots` of Node's retained snapshot exactly as of the last accepted retain fence (nothing later is claimed).
- *Root failure preserved:* `phaseRunFailure` (with its `failureSeq`) is fixed once by Node from the page-reported or Node-observed failure and is never replaced, edited or removed (§8 *Root failure*). *Cleanup evidence and later fatal detail are added, never substituted:* cleanup records follow the failure in `seq` order, a cleanup-evidence fatal is an additional `errorLedger.entries[]` entry with `seq > failureSeq`, and closeout causes go only to F `causes[]` / the journal `FAILED` detail; each can only add a `FAIL` reason.
- *R2 / R3:* R2 additionally renders exactly one line `failedRun: none | <source>/<category>/<phase>/seq <failureSeq>/<c1Stage>` (`none` on every non-failed run). R3 is unchanged — it references and verifies the failed-run R1 and R2 by SHA-256 exactly as for any run (R1's `schemaValid` uses the failed-run rules of §10); no new R3 key.
- *Terminal FAIL in K:* the authoritative K of a failed run is the ordinary K of §9.1 with `finalOverall = primaryOverall = FAIL`; K's schema does not change. The reader recognizes it as a failed-run K through R1 (§8 W-5/W-6).
- *Durably closed failed run:* R1 + R2 + R3 + J (journal ending `CLOSEOUT_STARTED`) + K all written and verified, with `K.finalOverall == FAIL` (reader W-6 ⇒ `FAIL` with `detail.failedRun`).
- *If any of these cannot be written or verified:* the existing closeout-failure path applies — step 10 (best-effort F + journal `FAILED`, no `linkSync`, no K) ⇒ reader `FAIL(commit-missing)` / `FAIL(closeout-failure-witness)` — and F carries the original `phaseRunFailure`, so the root failure survives a closeout failure. A failed run can never become `PASS` by any path.


### 9.2 Request-failure and HTTP-error classification (RC1 reconciliation + RC1-C1; fail-closed, no Viewer-domain allow-list)

*Scope (RC1-C1 — resolves H2 of the RC1 independent review).* This policy classifies two network event kinds on the G2 page and nothing else: (i) Playwright **`requestfailed`** events (network-level failures; `eventKind:'requestfailed'`) and (ii) **HTTP error responses** — every Playwright `response` whose `status ≥ 400` (`eventKind:'httpResponse'`). Playwright does **not** emit `requestfailed` merely because a response is 4xx/5xx, so the harness attaches passive `request`, `response`, `requestfinished` and `requestfailed` listeners from the Phase-0 `goto` onward (the `request`/`requestfinished`/`response` observations also feed the prefix-source ledger below). A response with `status < 400` (including 3xx redirects) is not a failure event. **Unchanged:** every `console.error` is fatal (empty allow-list, §9 above); the pinned-script integrity capture keeps classifying its own failed script request into `FETCH_FAILED` (§3, row 5) independently — a failed or ≥ 400 pinned Viewer script request is additionally FATAL here. The RC1 statement that HTTP error responses keep "no effect beyond the awaited Viewer operation's own success/failure" is **withdrawn**.

*Default and partition.* Every `requestfailed` event is **FATAL (required-resource failure)** unless it is **positively proven** an **EXPECTED_CANCELLATION** by the pure function below. There is no third non-fatal class and no list of tolerated Viewer/CDN hosts, paths or error texts beyond the closed conditions below; an unclassifiable event (a missing/invalid field, a classifier exception) is FATAL (`unclassifiable`). The harness performs **no navigation after the Phase-0 `goto`**; any navigation request failure after P0 is therefore FATAL. In the `ClassifierResult` below, FATAL is `classification ∈ {fatal-required-resource, unknown-fatal}` and EXPECTED_CANCELLATION is `classification:'expected-cancellation'`; a `requestfailed` event can never be `diagnostic-non-required`.

*HTTP response policy (RC1-C1; fail-closed).* Every `httpResponse` event (status ≥ 400) is **fatal by default** and can never be an expected cancellation. (R-1) `urlClass ∈ {bootstrap, harness-endpoint}` ⇒ always `fatal-required-resource`; no exception can ever apply. (R-2) `urlClass:'other'` ⇒ `fatal-required-resource` unless the event matches a **bounded expected-status exception** in the frozen constant `OPTIONAL_RESPONSE_RULES`, which is **empty in this procedure revision** — so in a live run under this revision every status ≥ 400 is fatal. A future procedure revision may add a rule only through its own review; each rule has the exact shape `{ruleId:string, method:string, model:'A'|'B', pathSuffix:string (exact, no wildcard, appended to a bound model prefix), resourceTypes:[('fetch'|'xhr'|'other'|'image')], statuses:[integer ≥ 400], rationale:string}`. (R-3) **Optional/diagnostic rule:** an event is `diagnostic-non-required` iff a rule matches on `method`, `resourceType`, `status` and `pathSuffix` (`pathSuffix` is a file name without `/`, matched exactly against the last path segment of `urlRedacted`), **and** the event is uniquely bound to `rule.model` (its `prefixKey ∈ modelPrefixes[rule.model]`, binding available, key not ambiguous — `boundPrefix` non-null), **and** its `startSeq` lies inside that model's `loadOperation` `expectedRequestWindow` (`operationId` = that load record), **and** `isNavigationRequest === false`. (R-4) **Ambiguous ownership is never non-fatal:** a rule match whose model binding fails (binding unavailable, key ambiguous, unbound, or bound to the other model) yields `unknown-fatal`, never `diagnostic-non-required`. (R-5) Unclassifiable (missing/invalid field, classifier exception) ⇒ `unknown-fatal`. **Two-stage classification (RC1-C1).** *Immediate (stage `immediate`):* a response that is **not a rule candidate** — R-1 applies, or no rule of `OPTIONAL_RESPONSE_RULES` matches its `method`, `resourceType`, `status` and last path segment — is classified at `responseSeq` and is **final at once**: `fatal-required-resource`, fatal at event time (it joins its correlated request identity's single fatal witness at `responseSeq`; `fatalCount += 1` only if this creates that witness — *Fatal-witness correlation* below), `finalizedSeq = responseSeq`. Required (non-optional) ≥ 400 responses are therefore always fatal immediately; with the live `OPTIONAL_RESPONSE_RULES = []` **every** response is immediate. *Provisional (stage `provisional`):* a rule candidate is recorded at `responseSeq` as a provisional entry with **no** verdict effect yet; it is **finalized** at `finalizedSeq` = the first of: the seq at which the later of the two load windows closes (both `loadOperation.endSeq` recorded), the gate-preparation step (§7 *Gate preparation*, strictly before `gateSeq`), or closeout step 1. At finalization R-3/R-4 are evaluated against `prefixDerivation` (which is fixed once both windows have closed); unresolved ownership at finalization (binding unavailable, ambiguous, unbound, other model, or not inside the rule model's window) ⇒ `unknown-fatal`, and fatality (the event's contribution to its identity's fatal witness — and, only if that creates the witness, `fatalCount += 1` with one fatal entry at `witnessSeq = finalizedSeq`) is committed **at finalization**, never earlier and never later; a provisional record's witness contribution is created at finalization. Because both load windows close in P1, a provisional record created in P1 is finalized before the gate and is counted in `fatalCountAtGate`. *Meaning of `eventTime` and `closeout`:* for an immediate entry, `eventTime` is the result computed at `responseSeq`; for a provisional entry, `eventTime` is the result computed at `finalizedSeq` over the record as it existed at `finalizedSeq`. At closeout step 1 the harness re-classifies every entry over the persisted record **truncated at the entry's `finalizedSeq`** (prefix-of-record semantics), so `closeout` is reproducible and must deep-equal `eventTime`. **Required/optional classification** is the retained field `requirement`: `'required'` for R-1 and for R-2 without a matching rule, `'optional'` only for R-3, `'unknown'` for R-4/R-5. **Diagnostic retention:** a `diagnostic-non-required` event adds nothing to `fatalCount` and has no verdict effect, but is retained in full in `responseFailures[]`; such an entry lacking its `rule` (= `ruleId`), `boundPrefix` or `operationId`, naming a rule absent from the frozen `OPTIONAL_RESPONSE_RULES`, or whose operation is not the `load` record of `rule.model`, is an evidence contradiction ⇒ row 5 `FAIL`. Required failures are never hidden by this path: R-1 precedes R-2/R-3 and every non-matching or ambiguous case is fatal. **Verdict effect:** `fatal-required-resource` / `unknown-fatal` ⇒ the event is a fatal raw event of its correlated request identity, whose single fatal witness contributes exactly one to `errorLedger.fatalCount` and one entry `{kind:'required-resource-failure', seq:witnessSeq, witnessId}` (*Fatal-witness correlation* below) ⇒ §8 row 1 `FAIL` (skip-to-cleanup unchanged).

*Harness-owned operation ledger `opLedger` (RC1; exact disjoint shapes RC1-C1 — resolves M2).* Before the harness invokes each load or mutation below it appends the record's start fields and **waits for the node-side acknowledgement** (same Playwright connection, so any browser event caused by the operation is received after `startSeq`); after the operation settles it records the end fields. Every entry is exactly one of two disjoint shapes, discriminated by `recordType`; all keys required, unknown keys rejected, `null` only where stated. **`loadOperation`** `= {recordType:'load', operationId:string, modelId:'A'|'B', modelUrnSha256:string, phase:'P1', startSeq:integer, startedAt:string, endSeq:integer|null, endedAt:string|null, expectedRequestWindow:{fromSeqExclusive:integer (= startSeq), toSeqInclusive:integer|null (= endSeq)}, prefixSourceRef:{entryIds:[string], ledgerSha256:string}, completionOutcome:'ready'|'rejected'|'timeout:load'|'harness-exception'|'not-settled'}` — `endSeq` is the seq at which readiness, rejection, the T2 expiry or the exception was observed (`null` with `'not-settled'` only if none was observed before closeout); `prefixSourceRef.entryIds` are the ids of every prefix-source entry with this `loadOperationId` and `ledgerSha256` equals `prefixDerivation.ledgerSha256`. A load record **never** grounds a cancellation. **`mutationOperation`** `= {recordType:'mutation', operationId:string, operationType:'hide'|'unload'|'teardown', teardownTarget:'closePage'|'closeContext'|'closeBrowser'|null, modelId:'A'|'B'|null, phase:'P9'|'cleanup', invokedBy:string ('C16' | 'C17' | 'cleanup:<step name>'), startSeq:integer, startedAt:string, ackSeq:integer, endSeq:integer|null, endedAt:string|null, cancellationWindow:{fromSeqExclusive:integer (= startSeq), toSeqExclusive:integer|null (= end(O) of C-d; null while open)}, causalEvidence:{spyRef:string|null, cleanupStepRef:string|null, ackSeq:integer}, terminalOutcome:'settled'|'threw'|'timeout'|'not-settled'}` with the exact coupling: `hide` ⇔ `viewer.hideModel(B)` in C16 (`modelId:'B'`, `teardownTarget:null`, phase `P9`); `unload` ⇔ a guarded model unload in C17 or a cleanup unload step (`modelId ∈ {A,B}`, `teardownTarget:null`); `teardown` ⇔ page/context/browser close (`modelId:null`, `teardownTarget` non-null, phase `cleanup`); `causalEvidence` points at the harness's own recorded invocation (spy-ledger entry or cleanup-step record) and repeats `ackSeq`. Nothing else can ground an expected cancellation; any other combination fails `validateResultSchema` (row 5). *Binding rule:* an `expected-cancellation` result names in `operationId` exactly **one** `mutationOperation` — the latest record satisfying C-c through C-e — whose `cancellationWindow` contains the event's `failSeq`; temporal overlap alone is never sufficient (C-a, C-b, C-c′ and C-e must also hold), and a result naming a `load` record, an absent record, or a record whose window does not contain `failSeq` is an evidence contradiction ⇒ row 5. `seq` is one node-side monotonic counter shared by `opLedger`, phase-boundary markers (`P0…P11`, `cleanup`, `closeout`), `check-finalized` events, `gates.C1`, control start/terminal records and request/response events.

*Model binding — prefix-source ledger and derivation (temporal overlap alone is **not** proof — RC1 review Critical; durable, recomputable evidence — RC1-C1, resolves M1).* **Prefix-source ledger** `errorLedger.prefixSourceLedger[]`: exactly one entry per **(`reqId`, `loadOperationId`) pair** such that the request's `request`-event `startSeq` lies inside that `loadOperation`'s `expectedRequestWindow` (an open window counts as extending to closeout), with `entryId = reqId + ':' + loadOperationId` (unique), ledger order ascending by (`startSeq`, `modelId` with `'A'` before `'B'`), exact shape `{entryId:string, reqId:string, loadOperationId:string, modelId:'A'|'B', startSeq:integer, terminalKind:'requestfinished'|'requestfailed'|'none', terminalSeq:integer|null, status:integer|null, method:string, resourceType:string, urlRedacted:string, urlClass:'bootstrap'|'harness-endpoint'|'other', isNavigationRequest:boolean, prefixKey:string (= origin + dirname(path) of urlRedacted), disposition:'included'|'excluded', reason:'included'|'excluded:resource-type'|'excluded:url-class'|'excluded:navigation'|'excluded:failed'|'excluded:status'|'excluded:not-finished-in-window'|'excluded:window-open'|'excluded:windows-overlap'|'excluded:ambiguous'}` (all keys required, unknown keys rejected; `reason` is the **first** applicable exclusion in the listed order, `'included'` iff none applies; `disposition` agrees with `reason`). An entry is **included** iff `resourceType ∈ {fetch, xhr, other, image}`, `urlClass === 'other'`, not a navigation request, `terminalKind === 'requestfinished'` with `200 ≤ status ≤ 299` and `terminalSeq ≤` its load's `endSeq`, the load windows are closed and disjoint, and its `prefixKey` is not ambiguous. **A candidate that later fails can never prove its own prefix:** a `requestfailed` request is `excluded:failed`, a ≥ 400 (or non-2xx) response is `excluded:status`, a request not finished inside its window is `excluded:not-finished-in-window`; and prefixes are **frozen when the load windows close** (both in P1), so every later candidate failure (EC-hide/EC-unload occur in P9/cleanup; R-3 responses inside a load window) is classified against the same frozen sets at event time and at closeout. **Derivation rule** `derivePrefixes(prefixSourceLedger, loadOperations)` (pure, deterministic): `candidateKeys[M]` = the `prefixKey`s of model-`M` entries meeting every inclusion condition except non-ambiguity; `ambiguousKeys = candidateKeys[A] ∩ candidateKeys[B]`; `modelPrefixes[M] = candidateKeys[M] − ambiguousKeys` (ascending). Binding is **available** iff both load records exist with `endSeq ≠ null` and their windows are disjoint (`A.endSeq < B.startSeq` or `B.endSeq < A.startSeq`); if unavailable, `candidateKeys`, `ambiguousKeys` and `modelPrefixes` are all empty and the affected entries carry `excluded:window-open` / `excluded:windows-overlap`. **Overlapping load windows are a valid runtime observation but a non-distinguishing state** (fatal-safe: nothing can bind): a request starting while both windows are open yields **two** entries (one per load operation, distinct `entryId`s), each receiving the first applicable reason (normally `excluded:windows-overlap`); both entries are part of the ordered ledger and of `ledgerSha256` and of the corresponding `prefixSourceRef.entryIds`, so the hash and the derivation are deterministic for the same input. The persisted **derivation record** `errorLedger.prefixDerivation = {algorithm:'g2-prefix-v1', loadOperationIds:{A:string|null, B:string|null}, windows:{A:{fromSeqExclusive:integer, toSeqInclusive:integer|null}|null, B:{…}|null}, bindingAvailable:boolean, nonDistinguishingReason:null|'no-load-operation'|'window-open'|'windows-overlap', candidateKeys:{A:[string], B:[string]}, ambiguousKeys:[string], modelPrefixes:{A:[string], B:[string]}, ledgerSha256:string, derivationSha256:string}` (`ledgerSha256` = SHA-256 of the canonical JSON of `prefixSourceLedger`; `derivationSha256` = SHA-256 of the canonical JSON of `{bindingAvailable, candidateKeys, ambiguousKeys, modelPrefixes}`; `nonDistinguishingReason` is `null` iff `bindingAvailable`). At closeout step 1 the harness **recomputes** `derivePrefixes` from the persisted ledger and load records and re-hashes both; any difference ⇒ `prefix-derivation-mismatch` ⇒ §8 row 5 `FAIL`. **Binding of a candidate:** an `EC-hide`/`EC-unload` candidate (or an R-3 response) is bound to model `M` iff `bindingAvailable` and its own `prefixKey ∈ modelPrefixes[M]`; then `boundPrefix := prefixKey`, `modelId := M`. *Ambiguous-prefix accounting.* A prefix key is **ambiguous** iff it is a candidate key of both models; the binding is **non-distinguishing** iff `bindingAvailable === false` (windows open or overlapping, or a load record missing). Retained: `errorLedger.ambiguousPrefixes[] = {prefixKey:string, sourceEntryIds:{A:[string], B:[string]}}` (exactly one entry per element of `ambiguousKeys`; all keys required; unknown keys rejected) plus `prefixDerivation.bindingAvailable` / `nonDistinguishingReason`. A candidate whose `prefixKey ∈ ambiguousKeys`, or any candidate while the binding is non-distinguishing, has observed binding status `ambiguous` and is classified **`unknown-fatal`** (reasons `prefix-ambiguous` / `binding-unavailable`; `boundPrefix:null`) — a **fail-safe fallback that can cost a false `FAIL` but never a false `PASS`**. `EC-teardown` needs no model binding: closing the owning page/context is itself the causal boundary (its `boundPrefix` is `null`).

*Captured fields (per event, all persisted redacted — no query string, §4.6).* `reqId`, `startSeq` (receipt of Playwright `request`), `failSeq` (receipt of `requestfailed`) or `responseSeq` (receipt of a `response` with status ≥ 400), `method`, `resourceType`, `urlRedacted` (origin + path), `urlClass ∈ {bootstrap, harness-endpoint, other}` (**bootstrap** = the pinned Viewer script/stylesheet URLs, the synthetic page document and `/clashpanel/**` modules; **harness-endpoint** = the operator server's `/api/auth/token`; **other** = everything else), `errorText` (exact `request.failure().errorText`, or `null`), `status`, `isNavigationRequest`, `frameIsMain`, `redirected`, `phase`, `activeCheck`. **Normative persisted shapes** (`validateResultSchema`, all fields required, unknown keys rejected): `requestFailures[i] = {reqId, reqIdValid, rawEventId, rawEventSeq, identityKey, duplicateOf, startSeq, failSeq, method, resourceType, urlRedacted, urlClass, errorText, isNavigationRequest, frameIsMain, redirected, phase, activeCheck, eventTime:ClassifierResult, closeout:ClassifierResult, agree:boolean}`; `responseFailures[i] = {reqId, reqIdValid, rawEventId, rawEventSeq, identityKey, duplicateOf, startSeq, responseSeq, stage:'immediate'|'provisional', finalizedSeq:integer, finalizedBy:'event'|'load-windows-closed'|'gate'|'closeout', method, status:integer (≥ 400), resourceType, urlRedacted, urlClass, isNavigationRequest, frameIsMain, redirected, phase, activeCheck, requirement:'required'|'optional'|'unknown', modelBindingObserved:{status:'unique'|'ambiguous'|'unbound'|'not-evaluated', modelId:'A'|'B'|null, prefixKey:string|null}, eventTime:ClassifierResult, closeout:ClassifierResult, agree:boolean}` — `phase`/`activeCheck` are the owning phase/check, `eventTime.operationId` is the operation-ledger reference, `modelBindingObserved` is the observed model binding (informational, never a verdict input), `requirement` is the required/optional classification of the HTTP response policy; **Cross-field rules (RC1-C1; semantic validation, mismatch ⇒ schema `FAIL`, row 5):** (i) `agree` is a **recomputed** field: `agree === deepEqual(eventTime, closeout)`; a stored value that differs from the recomputation, or `agree === false`, ⇒ row 5. (ii) `stage:'immediate'` ⇔ `finalizedBy:'event'` ⇔ `finalizedSeq === responseSeq`; `stage:'provisional'` ⇒ `finalizedSeq > responseSeq` and `finalizedBy ∈ {load-windows-closed, gate, closeout}`. (iii) **classification → `requirement` truth table:** `fatal-required-resource` ⇒ `'required'`; `diagnostic-non-required` ⇒ `'optional'`; `unknown-fatal` ⇒ `'unknown'`; no other combination (an immediate entry is always `fatal-required-resource`/`'required'`). (iv) **valid `modelBindingObserved` combinations:** `'not-evaluated'` ⇔ `stage:'immediate'`, with `modelId:null, prefixKey:null`; for a provisional entry (evaluated at `finalizedSeq`): `'unique'` ⇒ `modelId` non-null and `prefixKey ∈ modelPrefixes[modelId]`; `'ambiguous'` ⇒ `modelId:null`, `prefixKey` non-null and (`prefixKey ∈ ambiguousKeys` or `bindingAvailable === false`); `'unbound'` ⇒ `modelId:null`, `prefixKey` non-null, `bindingAvailable === true` and the key in neither `modelPrefixes` nor `ambiguousKeys`; a `diagnostic-non-required` entry requires `'unique'` with `modelId`/`prefixKey` equal to the result's `modelId`/`boundPrefix`. (v) `activeCheck ∈ {'C1',…,'C20'} | null` in both lists: `null` iff no check is executing at the event's seq (always `null` in P0, `cleanup` and `closeout`); when non-null, the check belongs to `phase` per the §5 phase order (C1 ⇒ P1; C2, C3 ⇒ P3; C4, C5 ⇒ P4; C7α, C18b ⇒ P5a; C7 ⇒ P5b; C6, C8 ⇒ P6; C20 ⇒ P6b; C9–C12 ⇒ P7; C13, C14, C15 ⇒ P8; C16, C17 ⇒ P9; C18 ⇒ P10 (C18a); C19 ⇒ P11; where C7/C18 appear in two phases either listed phase is consistent). `opLedger[j]` = one `loadOperation` or `mutationOperation` (above); `markers[k] = {seq, name ∈ {P0…P11, cleanup, closeout}}` (also persisted under `errorLedger.markers[]`); `prefixSourceLedger[]`, `prefixDerivation`, `ambiguousPrefixes[]` (above); `modelPrefixes` = `prefixDerivation.modelPrefixes` (persisted, after ambiguity removal). The unique causal operation of a `requestfailed` event is the **latest** `mutationOperation` `O` satisfying C-c through C-e; none ⇒ FATAL.

*Classifier result `ClassifierResult` (RC1-C1 — exact; resolves M2; all keys required, unknown keys rejected).* `{eventKind:'requestfailed'|'httpResponse', url:string (= urlRedacted), method:string, status:integer|null, failureReason:string|null, resourceType:string, phase:'P0'|…|'P11'|'cleanup'|'closeout', modelId:'A'|'B'|null, boundPrefix:string|null, operationId:string|null, opStartSeq:integer|null, classification:'fatal-required-resource'|'expected-cancellation'|'diagnostic-non-required'|'unknown-fatal', rule:'EC-hide'|'EC-unload'|'EC-teardown'|<a ruleId of OPTIONAL_RESPONSE_RULES>|null, reasons:[string], evidenceRefs:[string], verdictEffect:'fatal-row1'|'none'}`. **Exact nullability and coupling:** `eventKind:'requestfailed'` ⇒ `status:null`, `failureReason` = the exact `errorText` (or `null` when Playwright supplies none), `classification ∈ {fatal-required-resource, expected-cancellation, unknown-fatal}`; `eventKind:'httpResponse'` ⇒ integer `status ≥ 400`, `failureReason:null`, `classification ∈ {fatal-required-resource, diagnostic-non-required, unknown-fatal}`. `boundPrefix` and `modelId` are **non-null iff** the classification depended on a successful unique prefix binding — exactly `expected-cancellation` with `rule ∈ {EC-hide, EC-unload}` and `diagnostic-non-required`; they are `null` for `EC-teardown` and for **every** `fatal-required-resource` and `unknown-fatal` result (a fatal event's observed binding appears only in `reasons[]` / `modelBindingObserved`); when non-null, `boundPrefix ∈ prefixDerivation.modelPrefixes[modelId]`. `operationId`/`opStartSeq` are non-null iff the classification is non-fatal (`expected-cancellation` ⇒ a `mutationOperation` and its `startSeq`; `diagnostic-non-required` ⇒ the `loadOperation` of `modelId` and its `startSeq`). `rule` is non-null iff non-fatal. `verdictEffect = 'fatal-row1'` iff `classification ∈ {fatal-required-resource, unknown-fatal}`, else `'none'`. `reasons[]` lists every unmet condition (labels `C-a`…`C-e`, `C-c′`, `prefix-ambiguous`, `binding-unavailable`, `R-1`…`R-5`, `unclassifiable`, plus a sub-label `bootstrap | harness-endpoint | other`) and is empty iff non-fatal; `evidenceRefs` are JSON Pointers to the causal `opLedger` record, the `prefixSourceLedger` entries supporting `boundPrefix` and the bounding markers, non-empty iff non-fatal. **`unknown-fatal`** = the event could not be classified (missing/invalid field, unknown op shape, classifier exception) or its ownership could not be determined (binding ambiguous or non-distinguishing); every other non-qualifying event is `fatal-required-resource`. **No unknown or unclassifiable event can ever be non-fatal.**

*Classification functions* `classifyRequestFailure(event, opLedger, markers, prefixDerivation) → ClassifierResult` and `classifyHttpResponse(event, opLedger, markers, prefixDerivation, OPTIONAL_RESPONSE_RULES) → ClassifierResult` (the latter implements the HTTP response policy above) — pure, total, deterministic. For a `requestfailed` event, `classification = 'expected-cancellation'` **iff all** of: (C-a) `errorText === 'net::ERR_ABORTED'` (exact); (C-b) `urlClass === 'other'`, `isNavigationRequest === false`, and `resourceType ∈ {fetch, xhr, other, image}` (never `document`, `script`, `stylesheet`, `font`, never the bootstrap/harness-endpoint classes); (C-c) **in flight at the operation's start**: there is a `mutationOperation` record `O` with `event.startSeq < O.startSeq < event.failSeq`; (C-c′) **model-bound** (`EC-hide`/`EC-unload` only): `prefixDerivation.bindingAvailable`, the event's `prefixKey ∈ prefixDerivation.modelPrefixes[O.modelId]` and the key is not ambiguous (then `boundPrefix := prefixKey`, `modelId := O.modelId`); (C-d) **inside the operation's window**: `failSeq < end(O)` where `end(O)` is the first of {`startSeq` of the next `opLedger` record, the next phase-boundary marker, the `closeout` marker} that **already exists in the record** (if none yet, the window is open); (C-e) phase/kind coherence: `O.operationType ∈ {hide, unload}` ⇒ `event.phase ∈ {P9, cleanup}`; `O.operationType === 'teardown'` ⇒ `event.phase = cleanup` **and every check C1–C20 has a recorded final verdict** (teardown after completion). Rule labels: `EC-hide`, `EC-unload`, `EC-teardown`. Anything else is FATAL — `unknown-fatal` when unclassifiable or when C-c′ fails because the binding is ambiguous or non-distinguishing, otherwise `fatal-required-resource` — with `rule:null`, `boundPrefix:null`, `modelId:null`, `operationId:null` and `reasons[]` listing every unmet condition (and a sub-label `bootstrap | harness-endpoint | other | unclassifiable`).

*Timing and consistency.* Classification runs at event time over the record as it exists (boundaries not yet occurred are in the future, so the window is open); the harness **re-runs `derivePrefixes` and both classifiers over the complete ordered record at closeout step 1** (for `responseFailures[]` entries, over the record truncated at each entry's `finalizedSeq`, per the two-stage rule of the HTTP response policy) and any disagreement with an event-time result (deep inequality of the two `ClassifierResult`s) is `request-classification-mismatch` ⇒ §8 row 5 `FAIL`. Events after the terminal commit are ignored (unchanged).

*Verdict effect.* FATAL ⇒ the event is a fatal raw event of its correlated request identity; that identity's single fatal witness contributes exactly one to `errorLedger.fatalCount` and one entry `{kind:'required-resource-failure', seq:witnessSeq, witnessId}` (*Fatal-witness correlation* below) ⇒ §8 row 1 `FAIL` (existing mechanism; skip-to-cleanup unchanged). EXPECTED_CANCELLATION ⇒ **no** `fatalCount`, no effect on any verdict, but **every such event must be retained with its full evidence**: an EXPECTED entry missing any of `operationId`, `opStartSeq`, `startSeq`, `failSeq`, `rule`, or (EC-hide/EC-unload) `boundPrefix`/`modelId`, or whose operation is absent from `opLedger`, is not a `mutationOperation`, or has a `cancellationWindow` not containing `failSeq`, is an evidence contradiction ⇒ row 5 `FAIL`. HTTP responses follow the HTTP response policy above. `errorLedger.requestFailures[]` (all events, fatal and expected), `errorLedger.responseFailures[]` (all status ≥ 400 responses, fatal and diagnostic), `errorLedger.opLedger[]`, `errorLedger.prefixSourceLedger[]`, `errorLedger.prefixDerivation`, `errorLedger.ambiguousPrefixes[]`, `errorLedger.requestObservations[]`, `errorLedger.correlatedRequests[]`, `errorLedger.fatalWitnesses[]` and `errorLedger.witnessCount` are **verdict-critical fields exempt from truncation** (§4.6). No numeric threshold, count cap or time window is used (Table T rev-2 unchanged); the policy is not to be tuned on any live run.

*Fatal-witness correlation and counting (RC1-C2; exact one-to-one invariant — resolves M2 of the RC1-C1 independent re-review).* One network request can produce several raw events with the same `reqId` (e.g. a `response` with status ≥ 400 whose body transfer then fails ⇒ a later `requestfailed`). Fatality is therefore accounted **per correlated request identity, never per raw event**: exactly one fatal witness contributes to the verdict and to `fatalCount` per unique fatal request identity. This rule decides only *how many times* a fatal request counts (exactly once); it never decides *whether* a raw event is fatal — the classifier policy, the HTTP ≥ 400 fatal-by-default policy and the two-stage rule above are unchanged. All shapes below: all keys required, unknown keys rejected, `null` only where stated. **(W-1) Raw network event.** Every `requestFailures[i]` and every `responseFailures[i]` entry is one raw network event and is **retained in full** — never dropped, merged or rewritten, including duplicates and non-fatal events. Besides the fields above each carries: `rawEventId:string` (`'rf:' + failSeq` for `requestfailed`, `'hr:' + responseSeq` for `httpResponse`; unique), `rawEventSeq:integer` (`= failSeq` resp. `responseSeq`), `reqId:string|null` (the harness-assigned request id as captured; `null` if absent or not a string), `reqIdValid:boolean`, `identityKey:string`, `duplicateOf:string|null`. **Request observations** `errorLedger.requestObservations[]`: exactly one entry per Playwright `request` event on the G2 page from the Phase-0 `goto` on, ascending `startSeq`: `{reqId:string, startSeq:integer, method:string, resourceType:string, urlRedacted:string, urlClass:'bootstrap'|'harness-endpoint'|'other', isNavigationRequest:boolean, phase:'P0'|…|'P11'|'cleanup'|'closeout', activeCheck:'C1'|…|'C20'|null}` (plain JSON, redacted per §4.6, untruncated). `reqId` is allocated deterministically from request-object identity: at the `request` event the harness assigns `reqId := 'q:' + startSeq` to that Playwright `Request` object in an identity map (e.g. a `WeakMap`), and every later `response`/`requestfinished`/`requestfailed` event resolves `reqId` by looking up the same object (absent ⇒ `reqId:null`), so `reqId`s are unique; every `prefixSourceLedger[]` entry's `reqId` names exactly one observation whose `startSeq`, `method`, `resourceType`, `urlRedacted`, `urlClass` and `isNavigationRequest` it repeats (the prefix-source ledger references the observation ledger; a mismatch ⇒ `prefix-derivation-mismatch`). `reqIdValid` is **recomputed from `requestObservations[]`, never trusted**: `true` iff `reqId` is non-null and exactly one observation has that `reqId` and the same `startSeq`, `method`, `resourceType` and `urlRedacted` as the raw event; otherwise the event is **unclassifiable** and its classification is `unknown-fatal` (the existing missing/invalid-field rule). `identityKey = 'req:' + reqId` iff `reqIdValid`, else `'invalid:' + rawEventSeq` — a deterministic per-raw-event key, so an event without a trustworthy identity is never merged with another event and never suppressed. `duplicateOf` = the `rawEventId` of the earliest earlier raw event with the same `identityKey` **and** the same `eventKind` (a second `requestfailed`, or a second ≥ 400 `response`, for one request — e.g. a doubly delivered listener event), else `null`; a duplicate is retained, classified like any raw event and belongs to the same identity (it can worsen, never improve, the identity's classification, and never creates a second witness). Each raw event's **effective classification** is its `closeout.classification` (= `eventTime`, cross-field rule (i)); its **effective seq** is `rawEventSeq` for a `requestfailed` or an immediate response and `finalizedSeq` for a provisional response (a provisional member has no effect before its finalization). **(W-2) Severity order (total, worst first):** `unknown-fatal` > `fatal-required-resource` > `diagnostic-non-required` > `expected-cancellation`; FATAL = the first two. **(W-3) Correlated request identity** `errorLedger.correlatedRequests[]`: exactly one entry per distinct `identityKey` occurring in `requestFailures[] ∪ responseFailures[]`, ordered by the smallest member `rawEventSeq`: `{identityKey:string, identityKind:'reqId'|'invalid', reqId:string|null (non-null iff identityKind:'reqId'), rawEventRefs:[string] (the rawEventIds of every raw event with this key, ascending rawEventSeq, non-empty), eventKinds:[string] (the distinct member eventKinds, sorted), ownership:{status:'single'|'consistent'|'conflicting', modelIds:['A'|'B']}, worstClassification:'fatal-required-resource'|'unknown-fatal'|'diagnostic-non-required'|'expected-cancellation', fatal:boolean, fatalSinceSeq:integer|null, witnessId:string|null}`. *Ownership:* `modelIds` = the distinct non-null values of the members' `closeout.modelId` and (responses) `modelBindingObserved.modelId`, sorted; `status:'single'` iff one member, else `'conflicting'` iff `modelIds` has two elements, else `'consistent'`. *Classification:* `worstClassification` = the worst member effective classification by W-2, **except** that `ownership.status === 'conflicting'` (ambiguous model ownership within one request) forces `'unknown-fatal'` (fail-safe); `fatal === (worstClassification ∈ {fatal-required-resource, unknown-fatal})`. Differing `phase`/`activeCheck` between members is **not** a conflict (a request may answer ≥ 400 in one phase and fail at transport level in the next); each raw event keeps its own. `fatalSinceSeq` = the smallest effective seq of a fatal member, or — if no member is fatal and the identity is fatal only by an ownership conflict — the effective seq of the member whose arrival first made it conflicting; `null` iff `fatal:false`. `witnessId = 'w:' + identityKey` iff `fatal`, else `null`. **(W-4) Fatal witness** `errorLedger.fatalWitnesses[]`: exactly one entry per correlated identity with `fatal:true` and none otherwise, ascending `witnessSeq`: `{witnessId:string, requestIdentityKey:string, rawEventRefs:[string] (= the identity's rawEventRefs), fatalRawEventRefs:[string] (the members whose effective classification is FATAL; empty only for an ownership conflict), worstClassification:'fatal-required-resource'|'unknown-fatal' (= the identity's), witnessSeq:integer (= fatalSinceSeq), phase:'P0'|…|'P11'|'cleanup'|'closeout' and activeCheck:'C1'|…|'C20'|null (those of the raw event whose effective seq is witnessSeq), modelOwnership:{status, modelIds} (= the identity's ownership), ledgerEntryRef:string (JSON Pointer to its single `errorLedger.entries[]` record), eventTime:{worstClassification, witnessSeq, rawEventRefs}, closeout:{worstClassification, witnessSeq, rawEventRefs}, agree:boolean (recomputed: `deepEqual(eventTime, closeout)`; `false` ⇒ row 5), fatal:true}`. `eventTime` is the witness as maintained at event time — created when the identity first becomes fatal, later members appended and `worstClassification` worsened in place, never improved and never re-counted; `closeout` is recomputed from the retained raw events at closeout step 1. **(W-5) Counting.** When a raw event's effective classification becomes final (at `failSeq` / `responseSeq` for an immediate event, at `finalizedSeq` for a provisional one) and its identity is or becomes fatal **and has no witness yet**, the harness creates the witness, increments `errorLedger.fatalCount` by **exactly one** and appends **exactly one** entry `{kind:'required-resource-failure', seq:witnessSeq, witnessId}`; every later member of the same identity (fatal, non-fatal or duplicate) only updates the witness and **never** increments `fatalCount` or appends an entry. An identity that never becomes fatal has no witness (the EXPECTED_CANCELLATION and diagnostic retention rules are unchanged). Persisted count record `errorLedger.witnessCount = {requestObservations:integer, rawEvents:integer, correlatedIdentities:integer, fatalIdentities:integer, fatalWitnesses:integer, requiredResourceFailureEntries:integer, nonNetworkFatalEntries:integer, fatalCount:integer}`. **Invariant (validated by `validateResultSchema`, by the gate equations over `seq < gateSeq`, and at closeout step 1; stored values are never trusted):** `requestObservations = |requestObservations[]|`; every raw event with `reqIdValid:true` references exactly one observation; `rawEvents = |requestFailures| + |responseFailures|`; `correlatedIdentities = |correlatedRequests|` = the number of distinct `identityKey`s; `fatalIdentities` = the number of `correlatedRequests` with `fatal:true`; **`fatalIdentities === fatalWitnesses === |fatalWitnesses[]| === requiredResourceFailureEntries`**, the last being the number of `entries[]` of kind `required-resource-failure`, in bijection with `fatalWitnesses[]` via `witnessId`/`ledgerEntryRef`; **`fatalCount === errorLedger.fatalCount === fatalWitnesses + nonNetworkFatalEntries`**, where `nonNetworkFatalEntries` counts the fatal entries of every other kind (page error, unhandled rejection, `console.error`, crash/close, WebGL loss, uncaught injected error). Raw network events are **never counted directly**: no raw event, duplicate or second member of an identity contributes to `fatalCount` except through that identity's single witness. *Correlation cases (normative):* (a) `requestfailed` only ⇒ one identity, one witness iff it is FATAL; (b) HTTP ≥ 400 only ⇒ one identity, one witness iff FATAL (always, under the live empty `OPTIONAL_RESPONSE_RULES`); (c) both for one valid `reqId` (either order) ⇒ one identity with both raw events retained and **one** witness, classification the worse of the two by W-2, `witnessSeq` the first fatal effective seq; (d) missing/malformed/invalid `reqId` ⇒ `unknown-fatal`, `identityKey 'invalid:<rawEventSeq>'`, exactly one witness per such raw event; (e) conflicting model ownership within one identity ⇒ `unknown-fatal`, one witness; (f) duplicate raw events of one valid identity ⇒ all retained (`duplicateOf` set), counted once, one witness. **Unknown or ambiguous correlation can only make an identity fatal, never suppress a fatal.** *Closeout recomputation:* at closeout step 1 the harness recomputes every `reqIdValid` and `identityKey` from `requestObservations[]` (an invalid or absent reference ⇒ `invalid:<rawEventSeq>`), and `correlatedRequests[]`, `fatalWitnesses[]` and `witnessCount` from the retained raw events (closeout classifications); any difference from the persisted values — a stored `reqIdValid`/`identityKey` differing from the recomputation, a missing or extra identity or witness, a second witness or entry for one identity, a raw event counted directly, a `worstClassification` better than the recomputed one, a `witnessSeq` mismatch, `agree:false`, or a broken count equation — is `fatal-witness-mismatch` ⇒ §8 row 5 `FAIL`.

*Model-loss interaction.* A network-level request failure during a model load (X23), or an HTTP response ≥ 400 on a required resource during it (X27), is FATAL here and therefore `FAIL` (row 1 precedes row 6); `BLOCKED` for model loss (X4, §7 legality rule) arises only when the load failed **without** a fatal request failure or fatal HTTP response (e.g. classifier ≠ `CONFIRMED_SVF2`, the Viewer rejecting the awaited load, the T2 deadline).
