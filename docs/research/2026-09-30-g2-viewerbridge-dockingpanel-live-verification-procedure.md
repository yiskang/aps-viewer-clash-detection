### 4.1 Activation, authorization binding, and attempt journal (H1 of the v2 re-review)

**Interlock (all required):** CLI flag `--execute-live-g2`; env `G2_LIVE_AUTHORIZED=YES` (exact string); and **one explicit input `--authorization-record <repo-relative path>`**. Pure function `parseLiveActivation({argv,env})` returns `{authorized, reason, recordPath}`; `main()` throws fail-closed **before** any dynamic `import('playwright')`; no top-level playwright import; `chromium.launch` unreachable before the interlock and the record validation and the durable `AUTH_BOUND` write (source-order tests). The flag/env are not proof of owner authorization; the record below is.

**Authorization record — accepted artifact and deterministic selection.**

- *Type/path:* exactly one regular (non-symlink) UTF-8 markdown file located under `docs/prompts/` inside the repository, whose repo-relative normalized path (no `..`, no absolute path, no symlink component) is given by `--authorization-record`. The harness never searches for or infers "the latest matching prompt".
- *Required owner-authorization wording:* the file must contain each of the following as a whole line, each exactly once (any missing/duplicated/malformed line ⇒ reject):
  - `G2-LIVE-EXECUTION: AUTHORIZED EXACTLY ONE ATTEMPT`
  - `Authorization-ID: <lowercase [a-z0-9-]{8,64}>`
  - `Baseline-HEAD: <40-hex>` (must equal `git rev-parse HEAD` at run time)
  - `Procedure-SHA256: <64-hex>` (must equal SHA-256 of this procedure file's bytes at run time)
  - `Harness-SHA256: <64-hex>` (must equal SHA-256 of the harness file's bytes)
  - `Model-A-URN-SHA256: <64-hex>` and `Model-B-URN-SHA256: <64-hex>` (must equal SHA-256 of the literal URN constants in the harness)
  - `Runtime: viewer=7.124.2 env=AutodeskProduction2 api=streamingV2`
  - optional, zero or more: `Supersedes: <Authorization-ID>`
- *Ambiguity rejection:* the harness enumerates every regular `*.md` file under `docs/prompts/` that contains a line beginning `G2-LIVE-EXECUTION:` (the "candidate set"). It rejects if: the passed path is not in the candidate set; any candidate has malformed marker lines; two candidates carry the same `Authorization-ID`; or the number of **non-superseded** candidates ≠ 1 or that one is not the passed record.
- *Stale/superseded rejection:* a candidate is superseded iff another candidate's `Supersedes:` line names its `Authorization-ID`. The passed record must not be superseded.

**Reservation and journal — durable, per-authorization, monotonic.** Directory `test/acceptance/results/clashpanel-viewerbridge-g2-attempts/`. Two files per authorization: the **reservation** `<Authorization-ID>.reservation.json`, created **exclusively** (`open(path,'wx')`, which fails with `EEXIST` if any other process or earlier run created it) and never modified or deleted afterwards; and the **journal** `<Authorization-ID>.journal.json`, replaced by temp+rename **only by the process that owns the reservation**. The reservation carries the complete binding record (all binding fields below and the fresh `attemptId`); the journal repeats it and appends transitions. Content: `{journalVersion, attemptId (random UUIDv4), authorization:{path, sha256, id}, headSha, procedure:{path, sha256, version:'v5'}, harness:{path, sha256}, fixtures:{A:{name,urnSha256}, B:{name,urnSha256}}, runtimeEnvelopeRequested:{viewer:'7.124.2', env, api}, transitions:[{state, at (ISO-8601 UTC), monotonicMs, detail?}]}`. The `AUTH_BOUND` write carries every binding field; later transitions only append.

*States (exhaustive) and transitions (only these; each append is one durable write):*

| State | Meaning | Entered when | Exits to |
|---|---|---|---|
| `NOT_STARTED` | neither a reservation, a journal, nor any orphan temp file exists for this `Authorization-ID` | (implicit) | `AUTH_BOUND` |
| `AUTH_BOUND` | the record is validated and bound to HEAD/procedure/harness/fixtures/runtime; **nothing consumed**. This state is **boundary B3** of the canonical boundary sequence below (the journal carrying this transition is durable); the reservation (B1–B2) precedes it | **step W2b: the first durable act after record validation (after B1–B2), before every other fallible preflight step** | `PREFLIGHT_FAILED`, `ATTEMPT_CONSUMED` |
| `PREFLIGHT_FAILED` | a step after `AUTH_BOUND` and before consumption failed; the attempt is not consumed but **the record is spent** | any Phase 0 failure after `AUTH_BOUND` | terminal (a new run needs a **new** `Authorization-ID`/record) |
| `ATTEMPT_CONSUMED` | written and durable **before the first `loadDocumentNode`** | immediately before the first `loadDocumentNode` for model A | `CLOSEOUT_STARTED`, `FAILED` |

Carries `primaryOverall`/`primaryRow` only — no artifact hash. **It is the last journal transition of a successful run** | closeout step 2 | `FAILED`, or (success) the terminal commit **K**, which is a separate file, not a journal state |

Reachable only from `ATTEMPT_CONSUMED` or `CLOSEOUT_STARTED`, written best-effort **before** the commit attempt, and **never written once the K commit `linkSync` has succeeded**. It is diagnostic: correctness never depends on it, because a run without a valid K derives `FAIL` anyway. A journal whose history contains a `FAILED` transition anywhere derives `FAIL` | best-effort write on a closeout failure or abort | terminal |

**Canonical boundary sequence (single definition; every other section cross-references these names and never redefines a boundary).**

| Id | Name | Instant (all conditions complete) | Consequence |

**Durable write order (H1).** W0 parse interlock (pure). **W1 record validation** — read the record; enumerate and validate the candidate set and supersession; compute SHA-256 of the record, this procedure file, the harness file and the two URN constants; compare `git rev-parse HEAD` with `Baseline-HEAD`; scan the attempts directory (`readdir`, if it exists) for every `*.reservation.json`, `*.journal.json` and `*.journal.json.tmp-*` (startup rule below). W1 consists solely of local reads and pure computation: it touches no Viewer, model, token, browser, network or evidence file, and reserves nothing. **W2a establish the directory chain durably (reserves nothing), then W2b create the reservation exclusively (H1 of the v3 re-review).** *W2a:* `D0 = test/acceptance/` (tracked; must already exist), `D1 = D0/results/`, `D2 = D1/clashpanel-viewerbridge-g2-attempts/`. Every `Di` must be a real directory (`lstat`; a symlink or non-directory ⇒ refuse, exit 1). For `D1` and then `D2`, in this order: (1) if `Di` is absent, `mkdir(Di)` (an `EEXIST` race is accepted only if the result is a real directory); (2) open `Di`, `fsync(DiFd)`, close — makes the new directory's own entries durable; (3) open the parent `D(i−1)`, `fsync(parentFd)`, close — makes the parent's entry for `Di` durable. Step (3) runs **unconditionally, whether or not this process created `Di`** (an existing directory may have been created by an earlier process that died before its parent fsync; the fsync is idempotent). *W2b (only after W2a fully succeeded):* open `D2` and hold `D2Fd`; `open(reservation,'wx')` — on `EEXIST` refuse (another process or an earlier run owns this `Authorization-ID`); write the binding record; `fsync(fd)`; close; `fsync(D2Fd)`; then create the journal by temp+rename with the `AUTH_BOUND` transition (journal durability algorithm below, ending in `fsync(D2Fd)`). Any error from `mkdir`, `open`, `write`, `fsync`, `close` or `rename` in W2a/W2b is a durability failure: stop immediately, no retry, exit 1, no browser/Viewer/token access. Nothing fallible other than W2's own filesystem operations lies between W1 and W2; concurrent harness processes are serialized by the `wx` create — exactly one can win. **Durable-before-effect invariant:** no Phase 0 step, no CDN/token/Viewer/browser access and no W3 write occurs until W2a, the reservation's fsyncs and the `AUTH_BOUND` journal write (with its fsyncs) have **all** completed successfully. Consequently a reservation lost to an OS crash before its fsyncs completed implies that no external effect and no consumption happened, and the record is safely reusable; any reservation that any external effect could have followed is durable together with the directory entries that lead to it (the parent `fsync` of a freshly created attempts directory completed before the reservation was even created). **Only after W2 succeeds** may the harness perform the remaining Phase 0 steps (evidence-writer setup, harness/manifest hashing, git branch/porcelain clean-tree check, served-module manifest, Playwright import, browser/context/page/route/goto, bootstrap-ready, module install). Any failure in those steps ⇒ best-effort `PREFLIGHT_FAILED`. Then **W3 durably write `ATTEMPT_CONSUMED`**; only then the first `loadDocumentNode`. Boundary names are those of the canonical boundary sequence above (B1–B8). Pre-consumption use of the Viewer CDN script, token endpoint and `Initializer` is **not** consumption (G1 precedent) but does spend the record once B3 exists.

**Crash matrix and second-run rejection.** "Durable after" is the worst case after a crash; a *process* crash leaves everything the kernel accepted visible, an *OS* crash may lose anything not yet covered by a completed `fsync`.

| Crash / failure occurs | Durable state after | Same record reusable? | Reader class |
|---|---|---|---|
| during W0/W1 (no file operation on the attempts tree) | none | **Yes** — W1 is side-effect-free | none |
| during W2a: before/after `mkdir(D1)`/`mkdir(D2)`, after the new directory's own `fsync`, before/after the parent `fsync` (any subset may be lost by an OS crash; a process crash leaves any created directories, empty) | directory chain possibly absent, possibly present and empty; **no reservation** | **Yes** — no reservation was created yet (W2b starts only after every W2a fsync completed); no external effect occurred | none |
| a W2a durability step returns an error | as above; no reservation | **Yes** | none (harness exits 1) |
| during W2b after `wx` returned, before the reservation's `fsync(fd)`/`fsync(D2Fd)` completed: **process crash** | reservation visible (empty, truncated or complete) | **No** — existence alone spends the record | `CRASHED(reservation-only)` |
| same point, **OS crash** | reservation and/or directory may have vanished — or survive | **Yes only if nothing survived**; safe because of the durable-before-effect invariant (nothing external and nothing consumed had happened). If anything survives the record is spent | none, or `CRASHED(reservation-only)` |
| a W2b durability step returns an error after `wx` succeeded | reservation possibly visible | **No** (conservative: treated as spent if visible; harness exits 1 with no external effect) | `CRASHED(reservation-only)` if visible |
| reservation durable; final journal absent (orphan temp may exist) | reservation durable | **No** | `CRASHED(reservation-only)` |
| after `AUTH_BOUND` durable, before `ATTEMPT_CONSUMED` (or `PREFLIGHT_FAILED`) | `AUTH_BOUND` / `PREFLIGHT_FAILED` | **No** — record spent, attempt not consumed | `CRASHED(AUTH_BOUND)` if unterminated |
| after `ATTEMPT_CONSUMED` (B5) | `ATTEMPT_CONSUMED` / `CLOSEOUT_STARTED` / `FAILED`, and — only after B8 — the commit record K | **No** — attempt consumed | per §8 reader rule |

Because the entire directory chain, the reservation and its directory entry are durable **before** the first external effect, no crash can erase the only durable indication that an authorization was reserved or consumed while a later run silently reuses it: the only lossy window is the one in which nothing had yet happened.

*Startup rule (W1):* if `<Authorization-ID>.reservation.json` exists (in any content state), or `<Authorization-ID>.journal.json` exists in any state, or an orphan `<Authorization-ID>.journal.json.tmp-*` exists, or any reservation/journal in the directory has `authorization.sha256` equal to the passed record's SHA-256, the harness refuses (exit 1, fail-closed, reason `reservation-exists`, `journal-exists:<state>`, `orphan-temp` or `unreadable-reservation`). Reservation and journal files whose content cannot be parsed are compared conservatively: an unparseable `*.reservation.json` or `*.journal.json` in the directory ⇒ refuse (`unreadable-reservation`), never skipped. The W2 `wx` create repeats the same check atomically, so two processes that both passed W1 cannot both reserve. A refusal writes nothing. Only a new owner-issued record with a new `Authorization-ID` can license another run.

*Durability algorithm.* Directory chain: as W2a. Reservation: hold `D2Fd`; `open(reservation,'wx')` → write → `fsync(fd)` → close → `fsync(D2Fd)`. Each journal write (only by the reservation owner): `open(tmp,'wx')` in `D2` → write full JSON → `fsync(fd)` → close → `rename(tmp, final)` → `fsync(D2Fd)`; then reopen `final`, read bytes, compare SHA-256 to the intended bytes (write-success verification). Every other durable file in `D2` or `D1` (§9.1 R1–R3, K, F) uses the same write-`fsync(fd)`-close-`fsync(dirFd)`-verify sequence (F via `wx`; K via a `wx` candidate plus one non-overwriting `linkSync` commit, §9.1 step 8; R1–R3 via temp+rename in `D1`, whose own entry in `D0` was already made durable by W2a). **Realistic claim:** the state survives process crash and a normal (buffered) OS crash on a local POSIX filesystem (**except K**, which is atomically visible at B8 but durable only after the step-9 directory fsync; a loss reads `FAIL(commit-missing)`, §9.1 scenario 10); Node cannot request macOS `F_FULLFSYNC`, so **no power-loss durability claim** is made, nor any claim for network or FUSE filesystems; no claim is made about a filesystem that acknowledges `fsync` without persisting. The harness never deletes a journal or rewrites it to an earlier state. **Filesystem assumption (claim scope unchanged):** on the local POSIX filesystem `rename(2)` and `link(2)` are atomic, and a call that returns an error has not taken effect; nothing is claimed for network or FUSE filesystems.

*Failure handling per state:* a durability failure at W2a/W2b ⇒ exit 1 with no `loadDocumentNode` and no browser (a reservation that may exist is treated as spent); a journal write failure at W3 ⇒ no `loadDocumentNode` is issued (fail-closed; the run is a preflight-class failure, journal stays `AUTH_BOUND`); a closeout write failure ⇒ §9.1 (final verdict `FAIL`). **No retry is ever enabled by any failure.**

*Proof of exactly one attempt (what a later reviewer checks):* (1) the journal for the `Authorization-ID` shows exactly one `ATTEMPT_CONSUMED` transition and exactly one `attemptId`; (2) the result JSON's `attempt.attemptId` and every log line's attempt prefix equal it; (3) the spy/load ledger shows **zero to two** `loadDocumentNode` starts, ordered A then B, at most one per fixture, **none before** the `ATTEMPT_CONSUMED` timestamp, and exactly two only for a run that progressed through both load initiations (a consumed attempt that crashed or failed earlier legitimately shows fewer); (4) the journal's `authorization.sha256`, `headSha`, `procedure.sha256`, `harness.sha256`, fixture digests equal the values recomputable from the repository at the recorded HEAD (git history of the committed record); (5) exactly one reservation and one journal exist for the `Authorization-ID`, the reservation's binding record equals the journal's, and no other reservation/journal in the directory has the same record SHA-256; (6) the committed evidence set includes a byte copy of the journal, of R1, R2, R3, of the terminal commit record K (and of F if it exists); K's `resultSha256`/`summarySha256`/`manifestSha256` equal the SHA-256 of the committed R1, R2 and R3, K's `journalSha256` equals the SHA-256 of the committed journal, and the §8 reader function applied to the committed copies returns the verdict the report states.

**Phase 0 preflight (does NOT consume the attempt):** `W0 → W1 → W2 (AUTH_BOUND)` → start time + atomic evidence writer → harness sha256 → git branch/HEAD/porcelain (clean tree required; only `docs/prompts/` untracked allowed — the journal and result directories are git-ignored; the raw log, if any, is written **outside the repo tree** until copied — G1 lesson) → served-module manifest → Playwright import → browser launch/context (`serviceWorkers:'block'`, `deviceScaleFactor:1`)/page/route/goto → bootstrap-ready → module install. Any failure after `AUTH_BOUND` ⇒ overall `FAIL`-with-category, exit 1, journal `PREFLIGHT_FAILED` (best-effort), **attempt not consumed**, recorded separately (G1 precedent); a rerun needs a fresh owner record.

**Attempt consumed** at the completed `ATTEMPT_CONSUMED` durable write. From there: exactly one execution, no retry-until-green, no parameter/assertion/fixture change, no harness/production patch. A defect ⇒ preserve evidence, stop, independent review.

### 4.4 Deterministic target selection

Per model (A, B): enumerate the instance tree leaf dbIds ascending; candidate = leaf with ≥1 fragment and a valid `getNodeBox` (finite, min ≤ max). `a1` = first candidate of A; `b1` = first candidate of B. For the fit-union check (C6) choose the pair (`a*` from A, `b*` from B) among the first 50 candidates of each maximizing the world-space centre distance; ties by lowest dbId. Record all chosen dbIds, the full candidate counts, and the rationale. If no discriminating pair exists (N2) ⇒ C6 `NOT_EVIDENCED`. No selection is randomized.

### 4.5 Timeout contract

Every awaited Viewer/browser operation is wrapped in a token-bounded deadline (G1 token states; late completions quarantined and counted in `staleContinuationsDropped`). A timeout of an operation marks the current check `BLOCKED(timeout:<op>)` (or the control `TIMED_OUT`), sets `sessionTainted=true` when the operation was mutating or its completion is unknown, forbids further **mutating** Viewer calls except cleanup, and proceeds to cleanup. The timeouts that are **FAIL** not BLOCKED are exactly those named in §4.7 (c) E4/E5: absence of a **spec-expected event** within its window (negative evidence), expiry of the whole-attempt cap, and the Phase-0/cleanup step deadlines (via row 5/row 2). All values are frozen in §4.7 (Table T).

Readiness rule for tree enumeration: both models' `OBJECT_TREE_CREATED_EVENT` (or, if a tree already exists, `getObjectTree(cb)` success) **and** the geometry-loaded event as G1's load stages establish; a bounded poll only as G1's accepted fallback, recorded.

### 4.6 Evidence hygiene and call attribution

- **Redaction:** every persisted string (console text, failed-resource URLs, event payload summaries, headers) passes G1's secret redaction (drop query strings, mask bearer/`access_token`/signature patterns); the token response is never persisted. **Size caps:** per-field 4 KiB, spy ledger 2 MiB total, truncation recorded (`truncated:true, originalBytes`). **Verdict-critical fields are exempt from truncation** (verdicts, reasons, journal copy, scene-ownership table, oracle inputs/outputs); if they would exceed a cap the run's evidence write fails visibly rather than truncating them.
- **Wrapper composition and attribution:** all wrappers are created by one `recordingWrap` factory; injection wrappers (C15) are installed **inside** the recorder (recorder outermost). Call origin is assigned by a harness-controlled `withOrigin('harness'|'bridge'|'shell'|'viewer-internal', fn)` context stack, not by phase; a call with no active context is `unattributed`, and an unattributed call to a prohibited method is a C19 FAIL. Offline tests prove injected calls remain recorded and origin stacks nest.

### 4.8 Model ownership and cleanup semantics (M1)

- **What G2 loads:** the harness itself loads model A then model B through G1-style document/node load starters into one `GuiViewer3D`; it assumes nothing pre-loaded. **No registry/catalog/`ModelCatalog`/`wireModelUnload`/registration/re-registration/OQ-1 behaviour exists in G2**; models are raw Viewer `Model` objects, keyed by object identity (never `modelId`).
- **Owner of lifecycle:** the harness owns both models' lifecycle end to end. The ViewerBridge owns only its overlay meshes/scenes it created and its recorded isolation.
- **Allowed mutations of each model:** load; node hide/show (C11: one dbId, restored); model hide/show (C16: B only, restored); aggregate isolation set/restore (C10/C12/C14/C15); `unloadModel(B)` (C17, terminal, **not restored by design**); overlays via the bridge; the harness's own foreign overlay sentinels (§C7/C18). Nothing else.
- **What must be restored:** isolation empty; hidden nodes empty; hidden model shown (C16); harness-hidden node shown; harness sentinel meshes/scenes removed; recording/injection wrappers restored by reference.
- **What survives cleanup:** nothing Viewer-side: cleanup unloads every still-loaded model.
- **Model B after C17:** B has been unloaded by design; its object is stale. After C17 every read is guarded by `getAllModels()` membership; the harness never reloads B.
- **Cleanup — independent guarded unloads (`unloadModelA`, `unloadModelB`):** each step is attempted independently; if the model is absent from `getAllModels()` the step is `already-absent` (success); else `viewer.unloadModel(model)` with T8 deadline; failure recorded; then `verifyViewerModelSetEmpty`. These steps run even if C16/C17 were skipped, tainted or failed.
- **No-Panel-owned-residue proof for both models:** (i) bridge ledger `inspectLedger()===null` and `inspectDisposal()` clean; (ii) spy net `addMesh − removeMesh` = 0 for every Panel-owned scene; (iii) per §C18/§C7 the scene-ownership oracle passes; (iv) for each model still loaded at the check, aggregate isolation has no entry and hidden nodes has no entry; (v) for a departed model (B after C17) Viewer-side isolation/hidden state was destroyed with the model and is **not observable** — the claim for B is limited to (i)–(iii) and the pre-unload/post-`clear()` reads recorded in C17.

**C4 Element world-bounds: API validity and componentwise containment (H4).** *Purpose:* verify that the bridge's element-bounds path (used for outlines and fit targets) returns, for sampled elements, a finite world-space box that **fully contains the union of that element's fragment world bounds**; it does not assert equality, nearness or overlap.
- *Candidate bounds source:* the bridge's own path, `viewerApi.getElementWorldBounds(model, dbId)` (→ `getObjectTree()`/`getInstanceTree().getNodeBox(dbId, Float32Array(6))`, returned as `[minx,miny,minz,maxx,maxy,maxz]`), read with no harness transform.
- *Reference bounds source:* the union over **all** fragments of that dbId (instance-tree `enumNodeFragments(dbId, cb, recursive=true)`) of `model.getFragmentList().getWorldBounds(fragId, box)` (public reads; the same fragment-list frame the Viewer renders in). If any fragment's world bounds is unreadable, or the fragment list is empty, the dbId is `NOT_EVIDENCED` (the *full* reference union cannot be formed). **Declared independence limit:** both sources derive from Viewer fragment data, so this check verifies frame-consistency/containment of the bridge path against the fragment-list world frame; it is **not** the vertex-level reference that G1 F7 used and **does not resolve G1 F7**.
- *Coordinate space and transform handling:* both sources are compared exactly as returned, in the Viewer's world coordinates for that model; the harness applies **no** matrix, global-offset or unit conversion to either (unit scale is recorded only in C5). A frame mismatch (e.g. a node box lacking placement) therefore shows up as a containment deficit ⇒ FAIL — that is the check's purpose.
- *Exact inequalities (per dbId, per axis `a ∈ {x,y,z}`, native units):* with candidate `[bMin_a, bMax_a]` and reference `[rMin_a, rMax_a]`: `dMin_a = bMin_a − rMin_a` and `dMax_a = rMax_a − bMax_a` (positive ⇒ the candidate face lies **inside** the reference union, i.e. fails to contain it). `S_a`, `A_a`, `T_a` per Table T15. The dbId outcome is: `contained` iff **all six** `d ≤ A_a`; `NOT_EVIDENCED(near-tolerance)` iff no `d > T_a` and at least one `A_a < d ≤ T_a`; `FAIL(not-contained)` iff any `d > T_a`; **clause precedence (first match wins; the range checks run on all twelve coordinates — two 6-value boxes — before any subtraction or comparison arithmetic):** `FAIL(non-finite)` → `FAIL(out-of-range)` → `FAIL(no-bounds)` → containment clauses. `FAIL(non-finite)` iff any input is NaN or ±Infinity, or `bMin>bMax`; `FAIL(out-of-range)` iff all inputs are finite and any has `|v| > 2^900` (relabelling of the former single `FAIL(non-finite)` clause: both are FAIL outcomes exactly as before, and the two labels are distinguishable); `FAIL(no-bounds)` iff the candidate is null while the reference union was formed; `NOT_EVIDENCED(no-reference)` per above. Comparisons are strict `>` as written; a positive deficit above the PASS allowance **never** yields PASS.
- *Check verdict:* `FAIL` iff any sampled dbId is a FAIL outcome; else `NOT_EVIDENCED` iff any sampled dbId is `NOT_EVIDENCED` **or** the sample is empty; else `PASS` (every sampled dbId `contained`). Sample = the first 20 candidates of A and of B (T10; population and counts recorded; characterization of the sample, not a population claim). Excess candidate extent beyond the reference union (`bMin<rMin` or `bMax>rMax`) is recorded as observation statistics only (count, max ratio, per-axis) and is **never** a FAIL, never triggers the G1-F7 mechanism probe, a tolerance change or calibration. Also record the invalid-dbId behaviour (NaN pre-fill ⇒ `null`, no throw).
- *Failure evidence retained:* per dbId `{model, dbId, candidate box, reference box, fragment count, dMin/dMax per axis, S_a, A_a, T_a, outcome}`; per-run counts by outcome; the full candidate counts.
- *Negative control N6 (§7):* a pure in-run recomputation applying the same oracle to a **copy** of the first `contained` dbId's candidate box with one face moved inward — see N6.
- *Allowed conclusion:* for the sampled elements under this Viewer, the bridge's bounds path returns finite boxes that contain the fragment-list union within the frozen allowance (never `NOT_EVIDENCED`/FAIL outcomes present). Not allowed: any statement about unsampled elements, vertex-level tightness, or resolving G1 F7.

## 8. Overall verdict model — fail-first precedence (proposed — D2)

Per-check: `PASS | FAIL | BLOCKED | NOT_EVIDENCED`. `computeOverall(state, phase)` has exactly **two** operational phases, both evaluated **before K exists**: `phase='pre-closeout'` (after cleanup, §9.1 step 1; yields `primaryOverall`) and `phase='pre-link'` (the PASS-eligibility gate of §9.1 step 8(a): the same ordered pass over the *current* state plus **only the closeout predicates knowable before K exists** — `CLOSEOUT_STARTED` durable and verified, R1/R2/R3 written and verified, Kc written and verified, `snapshotEqual`, quiescence complete, no fatal event or overdue deadline since step 1, `closeoutFailures` empty; it returns the verdict the commit would carry, `preLinkOverall`). **There is no `phase='final'` evaluation and no evaluation of any predicate that depends on K.** `finalOverall` is not computed by `computeOverall`; it is *assigned* by the commit: `finalOverall = primaryOverall` synchronously iff `linkSync(Kc, K)` succeeds (the gate having required `preLinkOverall == primaryOverall`), and `finalOverall = FAIL` on any pre-link closeout failure or a `linkSync` error (§9.1 step 10). Each evaluation is a **single ordered pass; the first matching row returns; every row's predicate reads only recorded verdicts/ledgers/pre-link closeout facts (never the result of a later row), and every FAIL-producing row is evaluated over the full recorded set even when other checks are `BLOCKED`**. No later row can overwrite an earlier result, and a `BLOCKED` check record can never mask a FAIL elsewhere. The pre-link gate can only **worsen** a pre-closeout verdict (to `FAIL` via row 5 or, for a late fatal event, row 1), never improve it.

`sessionTainted=true` is a row-6 predicate in its own right, but any FAIL in rows 1–5 takes precedence. `PARTIAL` is not `PASS`. **Authoritative verdict rule — reader precedence over durable artifacts only (H2b).** A run's verdict is `deriveVerdictFromArtifacts(attemptsDir, resultsDir, authorizationId)`, a pure function of the files that survive; stdout, the exit code and the harness's in-memory state are informational and are **never** consulted. The result JSON's own `overall` field is `primaryOverall` and is never authoritative. **Terminal-commit invariant (v5):** a reader derives a run verdict only from K, K is created by one atomic non-overwriting `linkSync` strictly after every closeout verification succeeded (R1, R2, R3 and the K candidate all read back and verified), and after that synchronous `linkSync` returns success the harness performs **no** operation whose failure could change the verdict (only informational post-commit steps). Hence harness and reader cannot return PASS vs FAIL from the same durable artifact set: a `linkSync` error means K does not exist (reader `FAIL`); a `linkSync` success means K exists (reader = `K.finalOverall`, and the harness reports the same). Every partial prefix of the chain — a crash or fault at any step before the `linkSync` — derives `FAIL` (W-3/W-4/W-5). Exit codes follow the harness's `finalOverall`, which equals the reader's verdict for the same artifacts (the harness derives it from the commit outcome, not from a later re-read; the post-commit read-back, directory fsync and candidate unlink are informational and never change it): PASS 0, FAIL 1 (incl. any throw or Phase 0 failure **before B8**), BLOCKED 2, PARTIAL 3, unrecognized 4. **After B8 every operation is wrapped so that no exception, rejection or timer expiry can alter `finalOverall` or the exit code: the exit code is derived from `K.finalOverall` only.**

## 9. Error ledger and cleanup

**Error ledger** (G1 §6.6 semantics): `pageerror`, `unhandledrejection`, required-resource failure, crash/close outside cleanup, WebGL context loss, non-allow-listed `console.error` ⇒ fatal; `console.warn/info/log` never fatal; **empty allow-list by design**. The harness's own injected throws (C15) are tagged `injected`; an uncaught injected error ⇒ fatal.

**Cleanup ledger (ordered; every step runs; failures recorded, not blocking; each step bounded by T8):** `drainPendingTokens` → `bridgeDispose` (whichever bridge instance exists; await; idempotent) → `shellDispose` → `removeInjectedFailureWrappers` → `restoreRecordingWrappers` (originals restored by reference and verified) → `removeHarnessForeignScenes` (removes sentinels `S1`,`S2` and pre-created foreign scenes; **then** asserts each is absent) → `restoreIsolationEmpty` (harness) → `showHiddenNodes` → `restoreHiddenModel` → `verifyViewerStateBaseline` (isolation empty, hidden empty for every still-loaded model; no scene of any class remains; `sceneOwnership` table final rows recorded) → `unloadModelA` (guarded, independent) → `unloadModelB` (guarded, independent; `already-absent` after C17) → `verifyViewerModelSetEmpty` → `closePage` → `closeContext` → `closeBrowser` → `httpServerOwnership` (server not started by the harness; operator stops). Closeout (§9.1) follows the cleanup ledger and consumes its results. `cleanupUnresolvedOwnership` is true only if ownership remains unresolved after re-check ⇒ §8 row 2.

### 9.1 Closeout and evidence-write protocol (H2 of the v2 re-review; acyclic restructure H2a/H2b of the v3 re-review; terminal-commit redesign of the v4 re-review)

A run has a verdict only if **a terminal commit K was created after every required closeout/evidence condition was written and verified.** Evidence durability is a mandatory PASS condition: §8 row 8's **pre-link prerequisites** must hold at the gate, and `closeoutComplete` (K committed) is the resulting postcondition. Boundary names B1–B8 are those of the canonical boundary sequence in §4.1.

**Artifacts and acyclic dependency graph.** Every artifact is produced from facts that already exist when it is written; **no artifact contains its own digest or any fact that first exists at a later step.**

| Id | Artifact | Content (only already-existing facts) | Depends on |
|---|---|---|---|
| — | journal `CLOSEOUT_STARTED` (B7) | `primaryOverall`, `primaryRow`; no artifact hash | in-memory state |
| **S\*** | in-memory frozen snapshot (not a file) | the run state + `primaryOverall`/`primaryRow` + O2 status + journal transitions through `CLOSEOUT_STARTED`; deep-frozen at the **payload cutoff** (below) | state, `CLOSEOUT_STARTED` |

Dependency graph (arrows = "is computed from"): `state → CLOSEOUT_STARTED`; `{state, CLOSEOUT_STARTED, O2} → S*`; `S* → R1`; `S* → R2`; `{R1, R2} → R3`; `{R1, R2, R3, journal} → Kc`; `Kc → K` (byte-identical link). Acyclic; K's own bytes appear in no other artifact; every hash is recomputable by a reader from file bytes.

**R1 payload cutoff (immutable).** *Cutoff event:* the instant step 4 completes — `CLOSEOUT_STARTED` durable, O2 attempted, snapshot **S\*** taken as a canonical plain-JSON object (numbers, strings, booleans, `null`, plain arrays and plain objects only — no typed arrays, `Map`, `Set` or `Date`; the C20 RLE lists and matrices are plain number arrays) whose canonical serialization is hashed as `snapshotSha256`, and `Object.freeze`d recursively as a guard. *Allowed in R1:* exactly the top-level keys of §10 populated from S\* — including `attempt.journalStates[]` ending at `CLOSEOUT_STARTED` and `finishedAt` = the snapshot instant. *Closeout facts that exist only in R3/K/F/later records and are **forbidden** in R1:* any hash of R1/R2/R3/K/the journal after `CLOSEOUT_STARTED`, `closeoutFailures`, `requiredArtifacts`, `verification`, `finalOverall`, any commit or K field, and any journal transition after `CLOSEOUT_STARTED`. *Mechanical enforcement:* `buildResultPayload(S*)` is pure and deterministic; `R1bytes` is serialized **once** and sha256'd once; `validateResultSchema(result,'payload')` enforces a top-level key **whitelist** and a forbidden-key deny-list (unknown or forbidden key ⇒ invalid); before writing R3 and again before creating Kc the harness re-canonicalizes S\* and requires its hash to equal `snapshotSha256` **and** `buildResultPayload(S*)` to re-serialize byte-equal to `R1bytes` (`snapshotEqual`); any difference, or a thrown write to the frozen guard, is closeout failure `r1-mutated`. **O1 is external:** its existence is unknowable to the harness at the cutoff and is never recorded in R1 (only O2's status is). Offline tests inject a late mutation and assert the failure and a forbidden-key rejection.

**Optional artifacts** (**O1** raw log — captured by the operator's stdout/stderr redirect outside the tree, not written by the harness; **O2** PNG copies of the C20 frames): **only O2's** absence or write failure is recorded by the harness in `closeout.optional[]`; **O1 is captured externally by the operator — the harness neither writes, owns nor records O1's status; it is noted later by the reviewer/report and is never part of authoritative verdict reconstruction (§8 W-0…W-6 read only harness-owned files).** Neither has any effect on `overall`, `closeoutComplete` or the commit; no verdict-relevant datum lives only in an optional artifact.

**Order and verification** (each write uses the §4.1 durability algorithm; verification = re-open and read the bytes, compare SHA-256 to the intended bytes, and for R1 `JSON.parse`, `validateResultSchema` and `snapshotEqual`; a verification **read** may be repeated once, identically, before it is declared failed; a failed write is never retried; any write/rename/fsync/`link` error, read fault or mismatch that survives that repeat is a **closeout failure**, and there is no other kind of ambiguity: **an outcome that is not a verified success is a failure**):
1. Compute `primaryOverall = computeOverall(state, 'pre-closeout')` and record the error-ledger fatal count as `fatalCount0`. Required: all checks, controls and cleanup are finished (the browser/context/page are closed by cleanup) and evidence writing has not started; the whole-attempt timer (T9) is disarmed here and closeout has only its per-step deadlines (T8), any expiry of which **before the final critical section (step 8)** is a closeout failure, never a `linkSync` outcome.
2. Durably write journal `CLOSEOUT_STARTED` (B7, the fail-safe non-PASS witness); verify. Failure ⇒ closeout failure; go to step 10.
3. Attempt **O2**; its outcome never affects the verdict.
4. Freeze **S\*** (the payload cutoff).
5. Write **R1**; verify. Write **R2**; verify. Failure of either ⇒ closeout failure (skip to step 10).
6. **Only if R1 and R2 verified:** write **R3**; verify. Failure ⇒ closeout failure (step 10).
7. **Only if steps 2–6 all succeeded — Kc, then quiescence (asynchronous work is allowed here and only here):** create the candidate **Kc** (`open(...,'wx')`, write, `fsync(fd)`, close, `fsync(D2Fd)`); read back and verify the bytes; re-check `snapshotEqual` and that the journal bytes still equal those hashed. Then **quiesce every verdict-bearing asynchronous source**: (i) record, for every deadline the harness armed (T8 per-step, T9, poll deadlines), its absolute monotonic expiry `deadlineAbs` (`performance.now()` basis), then clear the timers and settle every deadline-wrapped operation (a late completion is quarantined and counted, never acted on) — clearing a timer can hide an overdue-but-undispatched expiry, which is why the gate re-checks `deadlineAbs` itself; **every promise the harness creates is tracked in a registry and either awaited to settlement (`Promise.allSettled`) or given its own rejection handler before the barrier — no un-awaited, un-handled promise may exist**, so verdict-bearing rejections are recorded by their own handlers rather than depending on the process-level `unhandledRejection` event; (ii) detach every Playwright page/context/browser listener and every Viewer spy/listener not already removed by cleanup; (iii) drain the event loop: `await` two consecutive `setImmediate` turns plus a microtask flush. **The critical section of step 8 is then entered as the body of a dedicated `setImmediate` macrotask scheduled from the last drain turn's callback — not as an `await` continuation.** Node reports `unhandledRejection` at the end of the tick in which the promise rejected, before the next macrotask starts, so every rejection created during the drain has already reached the ledger handlers when the step-8 macrotask begins (a rejection raised in the same tick as an `await` continuation could otherwise be reported *after* that continuation ran). Any expiry, mismatch, failure or ambiguity up to and including this drain ⇒ **no `linkSync` is attempted**; go to step 10.
8. **Final critical section (B8) — one synchronous, non-yielding block. Selected commit model: synchronous `fs.linkSync(Kc, K)`.** In this exact order and with **no `await`, no `yield`, no `.then`/promise construction, no timer or `setTimeout`/`setImmediate`, no `Promise.race`, no `AbortSignal`, no callback-taking `fs` call and no deadline wrapper** between the first statement and the statement after the `linkSync` returns: (a) *final pre-link eligibility gate:* evaluate `computeOverall(state, 'pre-link')` (§8) over the **current** state and error ledger — rows 1–8 with only the pre-link closeout predicates, **no K-dependent predicate** — and require `preLinkOverall == primaryOverall` with the same row as step 1 (for a PASS commit: `primaryOverall` is PASS-eligible and every row-8 prerequisite, including the closeout prerequisites, holds), `fatalCount == fatalCount0`, and — for every recorded `deadlineAbs` — that `performance.now() ≤ deadlineAbs` for each deadline governing a step not completed strictly before it (an overdue expiry ⇒ `late-verdict-change(deadline-overdue)`); **no `computeOverall(state, 'final')` exists and nothing is evaluated after the `linkSync`** (a fatal event delivered during steps 2–7 — page error, unhandled rejection, T9 expiry recorded, context loss — makes them differ ⇒ closeout failure `late-verdict-change`, **no `linkSync`**); (b) `fs.linkSync(Kc, K)`; (c) the whole block is one `try { gate (a); fs.linkSync(Kc, K); committed = true; finalOverall = primaryOverall } catch { committed = false; → step 10 }`: a throw from (a) or (b) sets `committed = false` and falls to step 10; **synchronously, in the same block**, on `linkSync` return, set `committed = true` and assign `finalOverall = primaryOverall` (by (a) already the pre-link-eligible verdict — PASS when a PASS is committed — so no evaluation is needed; `closeoutComplete` becomes true at this instant as a postcondition); on a thrown error (including `EEXIST`) set `committed = false` and fall to step 10. **Why no race remains:** JavaScript runs this block to completion on one thread, so no timer, promise continuation, event-emitter callback, queued task or fatal event *can* execute between the gate and the syscall result; an event delivered before (a) is seen by the gate, and one delivered after (c) is post-commit. `linkSync` is not wrapped by any deadline: a hung filesystem hangs the process and an external kill is a *crash* (truth-table rows 8–10), never a `FAIL` verdict selected while the link may later succeed. **Result is authoritative:** success ⇒ K exists and the verdict `finalOverall = primaryOverall` is committed; a thrown error ⇒ K does not exist (or is another run's and fails W-5's `attemptId` check) ⇒ reader `FAIL`. **Prohibited implementation patterns** (an offline **AST-level** test (not a token scan) whitelists exactly one direct `fs.linkSync(Kc, K)` call in the critical-section function — no helper, alias, getter or wrapper may reach a link primitive — and rejects each, a real-Node integration test suite (not only fakes) covers a promise rejection raised during the drain turn, an overdue timer, and an event queued around listener detachment (each ⇒ `late-verdict-change`, no link), and a negative control with an asynchronous late-link implementation — `fs.promises.link`, `Promise.race(link, timeout)`, or a fake filesystem whose link settles after a simulated timeout — must be rejected): any of the tokens above between the gate and the statement after `linkSync`; any asynchronous link primitive; any timeout able to select FAIL while a link may still create K. After (c) the harness performs **no** operation capable of changing `finalOverall` or the exit code: every later statement runs inside a catch-all, the process-level `uncaughtException`/`unhandledRejection` handlers ignore events once `committed === true`, and the exit code is derived from the already-assigned `finalOverall`.
9. **Post-commit (informational only, results printed, never affecting the verdict or the exit code):** `unlink(Kc)`; `fsync(D2Fd)`; read K back and compare. A failed directory fsync prints `PASS-UNCONFIRMED` (or the corresponding non-PASS verdict with `-UNCONFIRMED`) and `COMMIT_DURABILITY_UNCONFIRMED`; the exit code still follows `K.finalOverall`, but the operator must run the reader before accepting: an OS crash before the directory entry is durable can lose K and a later reader then returns `FAIL(commit-missing)` — the fail-safe direction; the operator must run the reader on the surviving files before accepting any run.
10. **Closeout failure path** (before a successful B8 commit): best-effort write **F**, best-effort append journal `FAILED`; `finalOverall = FAIL`, exit 1. This path is purely diagnostic — K does not exist, so the reader returns `FAIL` even if F and `FAILED` cannot be written.
11. Print `primaryOverall`, the closeout causes (if any), `finalOverall` and the post-commit observations; exit per §8.

**Reader/harness agreement (reconfirmed).** Exact-name K is the only verdict-authoritative artifact. If the harness reports PASS then `linkSync` returned success and a valid K existed at that instant; if K does not exist the reader cannot return PASS; the harness never reports FAIL after a successful `linkSync` (finalOverall is assigned in the same synchronous block and cannot be altered afterward).

**Ambiguity before B8 has no PASS path; B8 is atomic-visible, not power-loss-durable.** The v4 branch "K possibly landed but the harness reports FAIL" no longer exists: K is created only by a successful `linkSync`, and the harness treats *any* pre-commit uncertainty as failure by never calling `linkSync`; a `linkSync` that returns an error has not created K (this rests on the **stated filesystem assumption** of §4.1 — local-POSIX `link(2)`/`rename(2)` atomicity and "an error return means no effect" — which is an assumption to be accepted with D2, not a POSIX guarantee for every fault). The only harness-PASS/reader-not-PASS combination is the OS-crash-before-directory-fsync case of row 10, in which the reader is the fail-safe authority and the process that printed the result no longer exists to contradict it.

**Partial-artifact handling.** Temp and candidate files (`*.tmp-<uuid>`, `*.commit.candidate-<uuid>`) are never authoritative and are unlinked best-effort. A final-named R1/R2/R3 file that fails verification (before a successful B8 commit) is renamed best-effort to `<name>.invalid-<uuid>` and treated as **unwritten**; **K, once linked, is never renamed, unlinked, rewritten or otherwise touched by the harness**, and the `.invalid` rule applies to no file after B8. The reader rule of §8 (W-0…W-6) decides the verdict.
