| Tier | Meaning |
|---|---|

| **version-bound-7.124.2** | Undocumented Viewer state/event/method, or undocumented *semantics* of a public accessor, established only from the 7.124.2 bundle. Diagnostic/research-only. ## 2. Request identity: verification of D0's "none in Viewer"

**Confirmed [SRC].** The pinned 7.124.2 Viewer carries no request identifier anywhere on the navigation path:

- `Navigation.prototype.setRequestTransitionWithUp` (V:96723-96740) and `setRequestTransition` (V:96694-96710) store a plain destination object `{position, coi, fov, up, worldUp, reorient, pivot}` in the single slot `__destinationView` (init V:95294). There is no id, counter or caller field.
- `ViewingUtilities#update` (V:104994-105012) clears the slot with `setRequestTransition(false)` and then calls `transitionView(...)` with **destructured fields** (V:105006-105010). The slot object itself is not passed on.
- `Autocam#goToView` (V:106801-106817) **clones** those fields into a fresh `destination` that lives only in the `requestAnimationFrame` closure of `animateTransition` (V:107155). Autocam stores no destination property: A2 searched V:106560-107300 for `this.destination`, `_destination` and `lastDestination` and found no match.
- `CAMERA_TRANSITION_COMPLETED` is fired as `{ type }` only (`onTransitionCompleted`, V:26683-26686), and `transitionCompletedCallback()` has a single call site (V:107117).
- `TRANSITION_ACTIVE_FLAG_CHANGED` carries `{type, transitionActive}` only (V:96763).
- `cameraChanged` reuses one event object, `{type, camera: <live camera ref>}` (V:31839).

**Nearest identity-like handles. None of these is a request id:**

1. **Slot-object reference [SRC, version-bound].** Each `setRequestTransition*` call allocates a new object, so `getRequestTransition()` reference equality distinguishes *slot writes*. It does not distinguish *callers*, because any writer produces one (`fitBounds`, a non-immediate `restoreCameraState` at V:38655-38665, and other internal callers).
2. **Event payload content [SRC, public].** `FIT_TO_VIEW_EVENT` / `AGGREGATE_FIT_TO_VIEW_EVENT` carry the selection and `immediate` (V:36590-36603). This is content, not a token.
3. **Harness call-site identity [HAR].** The spy ledger record `callIndex`/`origin`/`atMs`/`argsDigest` (H:6886-6900) is the only true per-call identity, and it is **harness-tagged** (§3, O-1). Binding it to the slot-object reference (handle 1) would need a harness read of `getRequestTransition()` synchronously after the call. That is a version-bound read inside a harness-tagged correlation, and it can be done only in a separately authorized diagnostic.

**Facts most relevant to discrimination (no recommendation):**
1. The Viewer has **no request identity**. The only per-call identity is harness-tagged (O-1).
2. The only exact-instant consumption/start witness is version-bound O-8, and it is shared with view-cube and interaction transitions.
3. Pending-slot ownership requires version-bound O-5 bound to O-1 by a synchronous post-call read.
4. Public signals give tick boundaries (O-18), a likely zero-motion `cameraChanged` at consumption (O-15, [INF], unverified) and an uncorrelated end (O-16). None of them carries identity.
5. Frustum timing is fixed by T4 (O-26 = O-24's settled sample).

Whether any version-bound observable adds *demonstrated* discriminating value is for the package's §8/§10 experiment to show, not for A2 to assume.
