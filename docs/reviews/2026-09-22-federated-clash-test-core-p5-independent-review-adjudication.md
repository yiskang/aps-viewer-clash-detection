**Three new, non-blocking findings surfaced by the task reviewer's own `codex-review` pass** (not part of H1/H2/M1/M2, and confirmed — by direct trace of `claim.js`'s actual conjuncts, not merely accepted on Codex's say-so — not to reopen any vulnerability this task was authorized to close):

1. **High — definition-digest identity gap.** A tampered-but-internally-self-consistent, non-normalized `definition` (e.g. duplicated `selectionA` entries) can mint its own valid `semanticDigest`, so two differently-shaped definitions could pass as the "same" semantic test. `assessNoClashClaim`/`canClaimNoClashes` never read `resultSet.definition` at all, so this cannot by itself produce a false no-clash claim — it is a real identity/dedup-namespace gap, not a claim-safety bypass.
2. **Medium — H2 shape completeness.** Only the 8 sub-conditions this task was authorized to add are checked when `definition === null`; other ledger fields (`rootOwners`, `budgetExhausted`, `exclusions`, etc.) are not additionally constrained. `coverage: 'partial'` (already enforced) unconditionally blocks the claim predicate's `full` conjunct, so this gap cannot enable a false clean claim on its own — it is a "one true representation" completeness gap against the spec, not a bypass of what H2 was authorized to close.
3. **High (performance) — unsliced synchronous digest recomputation.** `computeSemanticDigest` now runs fully synchronously inside `checkCrossField`, while the rest of `validateResultSetSteps` is a slicer-yielding generator; measured ~140ms stall at a maximum-size (100k+100k selection) definition. This mirrors the brief's own explicit instruction to follow the existing synchronous `makeResultId`/`makePairId` pattern already in this file, so it is not an implementation defect against this task's brief — it is a genuine architectural/calibration question (plausibly a G-CAL concern, like other unmeasured caps already carried forward in the handoff) worth its own scoped follow-up decision.

These three are recorded here for the owner's visibility and disposition; none is treated as blocking this task's completion against its own authorized scope.
